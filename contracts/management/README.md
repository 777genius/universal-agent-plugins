# UAP management wire contract

`openapi.yaml` is the single editable transport schema. Go policy and prepared
objects stay private to the installer/application boundary. Generated DTOs never
carry authority to apply a change. The schema includes the private process
bootstrap/configuration documents so a non-TypeScript host follows the same protocol.

Run from the repository root with Go and Node >=22.18:

```sh
node contracts/management/generate.ts
node contracts/management/generate.ts --check
```

Generation reuses the pinned `oapi-codegen@v2.8.0` (models only) and
`openapi-typescript@7.13.0`. The generated TypeScript client uses `openapi-fetch@0.17.0`.
No runtime OpenAPI interpreter, server framework or custom generator is introduced.
Check mode creates owned temporary output, compares committed bytes and leaves
source unchanged. Request validation and authorization remain explicit Go behavior.

## Lifecycle contract

- One engine process captures one immutable environment/profile context.
- The trusted host writes one JSON `Startup` line to `manage serve` stdin, leaves it
  open and reads exactly one private `Bootstrap` line from stdout. EOF requests
  graceful shutdown. Diagnostics must not contain the capability.
- Every HTTP request sends bearer authorization and the exact bootstrap Origin.
- Prepare is read-only with respect to persistent installer state. It retains a Go
  prepared object behind an expiring ID. Apply rechecks current state.
- The host persists its request ID before apply. Accepted-request lookup precedes
  plan lookup/expiry. Same accepted identity observes prior work; changed input
  conflicts. After restart no serialized plan is executed automatically.
- Accepted work outlives its HTTP request. `operations.get` is authoritative;
  transport cancellation only stops observation. Explicit cancellation is
  cooperative and does not promise rollback.
- A terminal interrupted state with unknown effects omits `result`; it must not
  invent `mutated: false`. Inspect and prepare recovery/sync afresh.
- `environment.pendingOperations` exposes outstanding accepted work after host
  restart. It is not a complete history endpoint.
- Arrays in responses are non-null. Unknown future operation states are not success.
- API major version is separate from engine/package versions. Within v1, compatible
  optional response fields may be added; clients should ignore unknown fields.

The API does not expose arbitrary process execution or arbitrary filesystem
mutation. The host supplies trusted roots/executables once; HTTP intents use captured
target IDs. Plugin/Skill ownership, signature/release policy and updates stay in Go.

## Other languages

OpenAPI is the shared contract; another SDK must not port the installer. A future
Python client can be generated by OpenAPI Generator's stable `python` generator;
Java/C# clients can use the corresponding supported generator. Pin the chosen
version and configuration, keep generated code separate from the small ergonomic
wrapper, and run the same accepted-operation/cancellation fixtures. Do not modify
generated output. Avoid closed response-enum handling that mistakes a future state
for success, and do not enable automatic retries of unaccepted mutation identities.

`python_smoke.py` is a standard-library qualification client for this exact process
and HTTP protocol. It is deliberately a smoke client, not a published Python SDK.
It runs an actual fixture installation using the real engine and reports only
public session/operation metadata. Pass only disposable profile and state roots.
