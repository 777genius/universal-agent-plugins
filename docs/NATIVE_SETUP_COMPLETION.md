# Native setup completion

Current source extends a confirmed add/update/repair operation beyond file
delivery. Client adapters can complete exact project trust and selected MCP
approvals, then query the installed native client without a model request.
Repeating an unchanged Skills installation also refreshes its native result.
Plain saved status remains host-free.

The shared use-case capability retries setup only for an owned, verified,
allowed Prepared installation with certain native effects. Clients opt in;
other clients keep their existing behavior. An unclosed probe stops subsequent
client mutations. Trust and approval preferences survive plugin removal.

| Client | Observation and automatic setup | Limit |
| --- | --- | --- |
| Codex | Exact project trust, effective app-server configuration, owned Skill paths and selected stdio MCP status; native user plugin identity and version | No model turn or downstream service authentication |
| Claude Code | Native marketplace registration, exact scoped plugin/cache identity, selected MCP approval and native Connected health | Explicit disablement, ambiguous same-name plugins and managed policy remain authoritative |
| Gemini | Exact project trust, native Skill paths/content and selected MCP inventory | Qualification applies to the observed native schemas |
| OpenCode | Effective config, exact Skill content and selected local MCP connection in user/project scope | Connection evidence does not establish a tool call |
| Cursor | Exact selected MCP fingerprint approval and native server/tool inventory | The qualified approval schema is version-gated; unresolved interpolation stays Prepared. Skill/plugin discovery requires a signed-in native session |

Trust updates preserve unrelated settings through locked, conditional file
transactions. Cursor writes only the approval store and never invokes native
`mcp enable`, which can clear explicit disablement. Existing deny settings are
preserved and checked again before readiness is reported. Unknown schemas,
foreign ownership and uncertain cleanup never become successful activation.

Fresh native discovery/connection can qualify local stdio authentication as
not required. It does not erase explicit pending/failed authentication or
replace a catalog authentication requirement. Setup does not execute arbitrary
plugin tools: deterministic tool calls belong to isolated native E2E fixtures.

Local qualification uses disposable profiles and test projects, with no API keys
or model requests. Tool-call evidence is separate from discovery/initialization;
Cursor's login boundary remains visible. Historical pinned CI evidence and
released-client availability labels retain their original meaning.
