# Adversarial package-manager reliability: competitive regression gates

**Date:** 2026-11-01. **Status:** research / pre-implementation review. **Scope:** evidence-first follow-up to [UAP/APM risk PR #634](https://github.com/777genius/universal-agent-plugins/pull/634), not a finding that UAP contains the listed upstream defects.

## Decision and constraints

Target fewer **silent destructive or misleading-success** outcomes, not a broader feature checklist or unsupported claim of general superiority over Microsoft APM. Published APM 0.35.0 is the latest release observed on 2026-11-01; issues below are upstream reports at the named versions. A closed APM issue denotes a regression archetype, **not** an outstanding current APM defect. Only #634's completed artifacts justify the six-case comparison conclusions. A new UAP defect needs independent source-bound reproduction.

Keep Agent Plugins 1.0 / Agent Skills 1.0, existing Go package manager, file/receipt ownership, Clean Architecture and explicit source-scope support. No second resolver, state DB, daemon, policy DSL, silent force/adoption, feature flag, model login, broad client matrix or blanket promise of atomicity. **VS Code remains frozen per AGENTS.md.** Confirm product route eligibility and preserve exact released-version comparisons; current main tests cannot retroactively change UAP 0.1.95 results.

## Existing protection: do not duplicate

- [Six-risk E2E #634](https://github.com/777genius/universal-agent-plugins/pull/634): UAP **PASS** on exact parent-v2/child-v2 transitive update and post-pull removal; UAP **BLOCKED** on Claude cold no-receipts, A/B user profiles, deterministic post-write interruption, and MCP secret forwarding. It did **not** test multiple owners of one physical Skill, a local in-place changed parent, or a crash after an observed write.
- [Package-manager E2E](../../docs/testing/package-manager-e2e.md), `scripts/package-manager-e2e.py`, `cli/internal/agentpluginscli/testdata/package_manager_e2e_cases.json`: already cover deep/DAG/cyclic graphs, graph-edge replacement and unreachable-prune, cold portable restore, immutable pin replay, stale-lock metadata, foreign collisions, many CLI paths on 4 OSes. They do not automatically prove each narrowly defined adversarial scenario below. Extend this inventory only for genuine uncovered behavior.
- `cli/internal/agentpluginscli/deps_all_clients_e2e_test.go`, `deps_fresh_restore_e2e_test.go`, `deps_e2e_test.go`: existing composed lifecycle and ownership/retry coverage with fixture runner. `install/integrationctl/agentplugins/transaction/kernel_test.go` and `adapters/nativeconfig/kernel_test.go` cover durable journal and foreign MCP receipts. Tests against mocks and file IO are useful, but **not native-agent execution**.
- [Product follow-ups #641](https://github.com/777genius/universal-agent-plugins/issues/641) (real secondary Claude profile) and [#642](https://github.com/777genius/universal-agent-plugins/issues/642) (Codex target-qualified secret-name forwarding) own those capabilities. Avoid duplicate implementations here.

## First implementation slice (small, reusable, measurable)

**P0 pilot, at most four independent Go/CLI cases:** C4 unknown selected Skill; C5 old-cache/new-lock single replay; C2 two physical owners/cold clone (start with ownership representability spike); C1 deterministic post-write failure/recovery (start with exact transaction phase spike). C3's removed-child half is already substantially proved and must not be copied as a fourth duplicate. Before coding, map each to existing named case and its actual checks; extend the existing test rather than duplicate it. No N×agents×OS expansion.

**Later bounded pilots:** C3's **required-child omission** is distinct from the already-covered edge-removal case and runs only on a supported source/scope. C12 first evaluates existing signed **known-revocation, expiry and rollback** checks; online-only freshness is an unresolved policy choice. C6/C7 need narrow supported native Codex and Claude controls, separately from #641/#642. C8(a)/(b) and C11 are supported-host proofs (SSH/mixed-host/Windows) and remain BLOCKED/NOT_RUN without genuine host evidence. No additional P0 batch is implicitly authorized by severity.

## Distinct secret serialization check, not an ownership proof

**S1 — Claude project MCP canary** ([APM #3252](https://github.com/microsoft/apm/issues/3252)): a genuinely supported UAP project-MCP route, if available, gets an environment-variable reference and a random **synthetic** token. Read back exact project/user native config, portable files, lock, diagnostics and bounded temporary roots; no plaintext or common encoded canary may persist. Refusal/unsupported is not leakage or forwarding PASS. A native MCP subprocess must separately prove forwarding; config inspection alone cannot. This is not covered by C6's removal/ownership result, and [#642](https://github.com/777genius/universal-agent-plugins/issues/642) owns Codex-specific capability work. Do not introduce a portable `${TOKEN}` substitution rule under Agent Plugins 1.0.

## Mandatory negative controls / artifacts

1. Test old and new source contents independent of resolver output. Compare exact selected pins, `required_by`, stored/active tree hashes, native delivered bytes, foreign directory entries and owner identity. A self-consistent **incorrect** lock and installed tree is still FAIL.
2. Snapshot before any manager command; include portable inputs and unmanaged siblings. Exercise exact symlink, hardlink and same-byte replacement controls when selecting a scenario. Missing file/permission/symlink/race observations are BLOCKED, not absent. Same bytes with changed inode/mode/owner are not certified intact.
3. For controlled failure, record actual process phase and replay eligibility. Pre-write refusal may preserve all effects; post-write committed partial may legitimately need a journal/retry. Do not demand universal rollback or award PASS from a zero exit alone.
4. A source type, client version or hosted feature not supported in the pinned release is UNSUPPORTED with exact explanation. An unavailable private SSH server/Windows host is BLOCKED/NOT_RUN. Keep APM upstream reports separate from independently reproduced FAILs.
5. No real tokens, native model calls, implicit trust, force or external accounts. Synthetic canary checks never print values; no claim of total secret non-persistence without OS containment/detached-writer control.
6. Keep existing `scripts/package-manager-e2e.py` and `testdata/package_manager_e2e_cases.json` as the cross-OS executable catalog. Only high-risk oracle unit tests and real E2E cases; no second harness/service. CI path-scoped, no hourly timer or duplicated full CI.

## Pre-code critics and exit gate

- **Critic A — standard/scope:** for every gate, check Agent Plugins 1.0 / Agent Skills 1.0, existing UAP source kinds and installed target semantics; remove claims copied from APM without a matching UAP route.
- **Critic B — ownership/security:** challenge no-receipt restore, shared owners, TOCTOU, symlink/hardlink, private auth, canaries, post-write phase labels and false PASS due to unobserved directories.
- **Critic C — product/LoC:** delete redundant scenarios already proved in the portable E2E inventory; keep one high-value test per missing invariant. No new state service, policy engine, generalized chaos layer or vendor parity adapter.
- Apply the smallest actual product correction **only after** a new test fails against the supported route. Review patch and exact-hosted results. Merge when all relevant required tests and security reviews pass and observed outcomes are documented. No automatic release.

**Measured baseline:** Microsoft APM 0.35.0 was the latest non-prerelease GitHub release when checked (published 2026-10-22). This document records candidate bug reports, not claims that all remained unfixed on `main`; several APM issues (e.g. #3202, #3204, #3327) are closed. Sources are linked inline. #634's external observations remain the only independent comparison evidence already acquired.
