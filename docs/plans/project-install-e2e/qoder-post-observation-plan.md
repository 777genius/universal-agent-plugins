## Evidence and architectural decision

The [genuine populated artifact](../../evidence/project-scope-research/qoder-1.1.78-linux-amd64-40135008690/README.md)
at source2b0ef181 is verified independently by the author and Skillshare critic.

identical rows at each stage. Rows retain exact projectPath attribution, but all
three payloads occupy the original user's shared plugin cache and the user's
registry changes. A/B remain empty in these **non-Git** fixtures. Different
versions were used; actual selected skills, same-version cache behavior, native
update/uninstall, Git-root behavior and runtime isolation are not established.
All eight original qualification fields remainfalse.

Do not turn the native `scope:project` label into project-owned files or treat
list visibility as loaded selection. Do not rename the portable plugin identity,
redirect HOME, delete a native cache directory or rewrite native registry JSON.
The existing user adapter is preserved, including its conservative refusal of
unrecognized/duplicate global rows. This slice does not qualify same-name native
user/project coexistence for that existing user lifecycle.

Implement a narrow **Prepared project skill bundle** using the already supported
Qoder plugin format. Its files are owned by the selected project's UAP namespace;
UAP does not register it in the native user registry. The bundle contains standard
skills and eligible portable commands rendered as skills. Project MCP, hooks,
agents and other unobserved native resources remain unsupported in this slice.
This is useful project installation with an explicit native import boundary,
not automatic native project activation.

## Projection and local ownership

The actual importable native view is a closed subdirectory
`<active>/.agentplugins-qoder-native/`, containing only the generated
`.qoder-plugin/plugin.json` and selected `skills/<name>/` trees (including
rendered eligible commands and their selected skill assets). Reuse the existing
Qoder manifest/skill encoding, not a second loader. Reject a source collision
with the reserved projection subdirectory before publishing. Keep original
standard package/source payload outside that native view and preserve immutable
source bytes. Manual import must point at this exact view, never the whole
managed package. Unknown root auxiliary native files therefore cannot cross the
import boundary: no raw `.mcp.json`, hooks, agents or other native discovery
surface is copied into this closed view. Verify its complete allowed path set,
manifest skill declaration and absent unselected native resources before final
file verification. Do not solve this by merely omitting mcpServers while copying
an authored raw native config/hook into the same importable root.

Validate staging as a real contained direct child of the exact managed base and
active path as the exact selected physical artifact. Reuse the prepared namespace
scanner, which already recognizes `.qoder-plugin/plugin.json`, for duplicate,
foreign and malformed manifest claims. Existing full managed-directory digest and
receipt checks remain required; RegistryClear is only namespace evidence.

The project PreparedRegistryInspector carries local package/namespace findings.
The project branch of InspectNativeRegistry validates exact authority and then
returns neutral RegistryClear; it must never return a positive RegistryExpected
merely because a prepared package exists. Errors/collisions may still refuse.
That neutral native finding cannot set NativeDiscoveryReconciled. A project
NativeRegistryExecutable stays empty, so NativeDiscoveryAttempted also stays
false even when the SDK enables its observer with a supplied forbidden runner.
Neither branch calls plugins list/install/uninstall. A native
same-name user row is not a collision for materializing an independently owned
bundle; it does not make that bundle active. Before first add, a clear absent
managed target is admissible; an unowned same-name/physical claim refuses. With
receipts, exact digest identity is required; tampered bytes refuse or follow the
existing reviewed known-drift repair contract without adoption.

NativeObjectOwnership contains only the exact managed_package_directory receipt;
no native cache/registry/profile/data ownership is manufactured. Bindings validate
scope/client/physical ID/selected profile/locator and reject foreign object kinds.

## Lifecycle and truthful verification

AutomaticallyActivates is false for project scope. Preflight validates selected
identity and rejects ActivationComplete before state effects, including first
add and replay/update/repair after reopening. Early unstaged preflight permits an
empty delivery but checks every supplied identity. Final activation requires the
exact populated delivery and declared name before returning a result.

Return Prepared with file installation_verified only after the real managed
package/projection verifier proves the exact installed skill bundle. This field
means installed bundle files; no native discovery or runtime claim follows. A
runner-free read-only project verifier uses the same package/receipt evidence;
absence, changed bytes, unknown projection or foreign claims cannot pass it.
Its outcome has NativeEffectUnchanged, no attestation and no newly invented
native objects. Existing generic proven Prepared no-change logic may then keep
actual repeat add/unchanged update/intact repair Mutated=false. If this composed
route exposes a generic convergence gap, freeze a separate concrete correction
plan; never weaken the proof or silently report a write as unchanged.

All project add/update/repair/inspect/remove/recover paths preserve the original
user authority and other project. Removal validates the recorded bundle identity
and removes only UAP's exact directory through the existing transaction; it never
calls native uninstall or removes a native/user cache. Persistent caller-owned
project data remains untouched. Ordinary status remains host-free.

## Native use and explicit remaining limitation

User actions identify the exact compatible native view directory
`<active>/.agentplugins-qoder-native/` and project working directory. The observed native importer accepts local `.qoder-plugin/plugin.json`
and skill files. If an operator chooses native registration, the explicit argv
is `plugins install <exact-native-view> --scope project --json` from the selected
project directory; UAP does not execute it. Explain that this operation writes
the user's native registry/cache, and same-name/same-version replacement remains
unqualified. Require operator review of existing native registrations/cache before
that separate action. No `/plugins reload`, trust approval or model task is run.

A manually imported cached skill copy is native state independent of UAP's bundle
receipt. UAP remove does not unregister or delete that copy; native cleanup is a
separate native project-scope operation and must be reviewed independently. No
stdio/MCP path into the bundle is projected in this slice, so this guidance does
not create an owned executable registration pointing at a later deleted package.
Do not suggest that bundle removal undoes manual native/global changes.

A later automatic native project-registry route would need additional actual
Git/non-Git and same-name/same-version observations, native scoped update/remove
with user/A/B preservation, cache/body ownership semantics, and actual fresh
runtime skill selection. The current global list schema is insufficient. Such
work requires its own two plan rounds and actual native evidence before promotion.
