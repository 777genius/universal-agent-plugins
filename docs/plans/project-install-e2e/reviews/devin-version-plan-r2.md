## Evidence and reasoning

The proposed optional operational `installer.Request.ClientVersion` is a narrow repair to an observed composition gap. The existing detector pairs its normalized version with its selected primary executable, while both `runInstallerFacadeLocalAdd` and `dependencyInstaller.Prepare` currently forward the executable without the version. `Engine.detectedClient` reconstructs the selected client and currently drops that evidence. Copying the host-supplied string into `DetectedClient.Version` preserves the existing detector and SDK Discover no-execution contracts. `clonePrepareRequest` begins with a value copy, so a string remains frozen in the prepared request without another mutable evidence object. Keeping the field excluded from diagnostic JSON and absent from portable manifests avoids package-authored qualification.

For the project lane, `backendExecutable` returns the nonempty selected executable before considering sibling fallbacks. Windsurf detection deliberately selects `windsurf` ahead of `devin` in coexistence environments. The amendment correctly preserves this legacy ordering and requires both the selected basename `devin`/`devin.exe` and exact normalized `3000.11.205` evidence. Presence of a secondary Devin surface, an editor installation, a version from another executable, a missing version, or a different/older version must not qualify the lane. The existing version normalizer extracts a version token; implementation tests must establish exact equality, including rejection of unrelated suffix/prerelease values rather than a loose numeric prefix or minimum-version comparison. This host assertion remains configuration admission, not proof of binary provenance or native runtime discovery.

Saved install, update and repair reach the common `dependencyInstaller.Prepare` request builder, so forwarding fresh selected detection there covers all three. `compatibilityChecks` reconstructs observational clients, but `compatibilityBindingCheck` explicitly restores `target.Client` for the selected client; its prepared version therefore survives the selected update compatibility preview. No new version fields are needed in the existing Claude/Codex-only group target contract. The adapter gate must apply to new configuration preparation and activation, rather than broadening `ReserveIdentity`'s layout-only prospective identity calculation into another detector. No version probe, stale recorded version, retained package metadata, or manifest field may substitute for fresh request evidence on install/update/repair.

Exact owned removal is deliberately version independent and launches no native cleanup. Configuration/transaction recovery is likewise driven by the existing observed scope, physical authority, journals and receipts; it must not become a request for a current Devin executable/version or implicitly re-run installation. A separately requested post-recovery sync obtains fresh selected host evidence as usual. Missing/changed harness evidence must therefore prevent new installation or repair while allowing safe exact removal/recovery of recorded authority.

The additional absent-profile clause addresses a real composition mismatch: current-only Devin detection legitimately yields no legacy Cascade ConfigRoot, `NewTargetContext` already allows an absent original user root, and `detectedClient` presently requires one unconditionally. Allowing absence only within an already validated project engine/request is coherent. A nonempty root remains clean and absolute; user scope retains its required-root contract. Existing profile resolvers and client-specific stricter checks remain in force. Both-empty original user context is legitimate, while any nonempty context mismatch must fail. Project authority must derive from the explicit project root and its exact native layout/artifact/receipts, never a fabricated legacy profile or an empty-root fallback.
