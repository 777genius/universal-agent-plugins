# Grok public repair in the existing native journeys

## Review boundary

This is a follow-up to the reviewed Project enablement product candidate.
It must be composed with that candidate after product review. It does not
change the older generic native API research, User integration, ACP metadata
admission or foreign-MCP tripwire. Their original negative results remain
negative until an explicit measured replacement is accepted.

Both existing native journeys retain their local source and `--no-save`
installation. Their original EnvironmentAuthority is therefore nil. No saved
receipt is invented, and their native qualification is limited to the actual
unmanaged Project lifecycle. Saved-dependency consent and recovery are tested
separately through the public SDK and the actual Cobra TLS ZIP fixture.

## Changes

The existing fixture still authors explicit trust for its disposable projects.
It no longer manually enables a plugin by its bare name. Each journey invokes
public `repair <exact-installation-id> --target grok --scope project
--confirm-plugin-enable --yes`, reads the settled full-ID ownership receipt,
and verifies repeat repair leaves the exact member and receipt unchanged.
Activation remains Prepared.

Native before/after config bytes must equal the one expected full-ID insertion
or removal. Other protected fixture files must still match their recorded
contents. No general config write exemption or whole-file restoration is used.
Update/repair and each later protocol stage must retain the same acknowledged
enablement receipt. Immediately before removal, the test authors a later foreign
array member and table; public removal must preserve those exact bytes.

The local deterministic provider now replaces only its previous exact authored
suffix. It reads the current remaining config first, preserving later foreign
edits and the product's removal of the owned member. Reusing the initial cached
prefix would have reintroduced enablement during the post-removal negative
session, so a specific inert regression covers that risk.

## Evidence limits

Ordinary no-consent repair and consented dry-run must preserve native config,
whole ownership state, and MCP witness events in the genuine native journey.
This process capture does not observe the installer's internal ACP argv. It
therefore explicitly does not claim to prove zero internal ACP executions.
Both workflows additionally run the actual public saved Cobra consent fixture,
which proves zero ACP calls for no consent, dry-run, decline and EOF at its
inert vendor transport boundary. The workflow admits one exact passing Go test
event, so an absent or renamed test cannot pass as an empty selection.

The existing doctor/direct MCP distinction and native deterministic-provider
call evidence remain intact. The new unmanaged Project ownership qualification
stays false until the entire genuine journey, removal, retained-data checks,
source/binary integrity checks and ordinary negative cases succeed. None of
these source edits or inert tests is native qualification by itself.
