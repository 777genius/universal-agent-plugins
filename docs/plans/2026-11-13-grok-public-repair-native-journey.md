# Grok public repair in the existing native journeys

## Review boundary

This is a follow-up to the reviewed Project enablement product candidate.
It must be composed with that candidate after product review. It does not
change the older generic native API research, User integration, ACP metadata
admission or foreign-MCP tripwire. Their original negative results remain
negative until an explicit measured replacement is accepted.

Both existing native journeys retain their local source and `--no-save`
installation. Their original EnvironmentAuthority is therefore nil. No saved
receipt is invented, and their native qualification is limited to the actual
unmanaged Project lifecycle. Saved-dependency consent and recovery are tested
separately through the public SDK and the actual Cobra TLS ZIP fixture.

## Changes

The existing fixture still authors explicit trust for its disposable projects.
It no longer manually enables a plugin by its bare name. Each journey invokes
public `repair <exact-installation-id> --target grok --scope project
--confirm-plugin-enable --yes`, reads the settled full-ID ownership receipt,
and verifies repeat repair leaves the exact member and receipt unchanged.
Activation remains Prepared.

Native before/after config bytes must equal the one expected full-ID insertion
or removal. Other protected fixture files must still match their recorded
contents. No general config write exemption or whole-file restoration is used.
Update/repair and each later protocol stage must retain the same acknowledged
enablement receipt. Immediately before removal, the test authors a later foreign
array member and table; public removal must preserve those exact bytes.

The local deterministic provider now replaces only its previous exact authored
suffix. It reads the current remaining config first, preserving later foreign
edits and the product's removal of the owned member. Reusing the initial cached
prefix would have reintroduced enablement during the post-removal negative
session, so a specific inert regression covers that risk.

## Evidence limits

Ordinary no-consent repair must preserve native config, existing ownership and
MCP witness events while committing its normal package-directory replacement.
Consented dry-run must preserve the complete verified post-repair state bytes.
This process capture does not observe the installer's internal ACP argv. It
therefore explicitly does not claim to prove zero internal ACP executions.
Both workflows additionally run the actual public saved Cobra consent fixture,
which proves zero ACP calls for no consent, dry-run, decline and EOF at its
inert vendor transport boundary. The workflow admits one exact passing Go test
event, so an absent or renamed test cannot pass as an empty selection.

The existing doctor/direct MCP distinction and native deterministic-provider
call evidence remain intact. The new unmanaged Project ownership qualification
stays false until the entire genuine journey, removal, retained-data checks,
source/binary integrity checks and ordinary negative cases succeed. None of
these source edits or inert tests is native qualification by itself.

## Ordinary repair state correction

The initial preview helper incorrectly required whole-state byte equality
around ordinary `repair --yes`. The actual public route is `runRepairMany` and
the existing grouped lifecycle deliberately restages an intact package. This
is independent of native enablement consent. The existing actual Cobra
`TestProjectGrokPublicGroupedRepairRestagesIntactAndMissingPackage` passed on
`2b557b30e` in 0.368 seconds with a logging-only overlay; its requests,
assertions and production source were unchanged. The inspector is inert, so
this result does not qualify the vendor runtime.

The recorded state/DTO pair changes exactly four locations: the installation
operation group, equal installation/binding update timestamps, and one appended
committed directory-swap receipt. The new consumer reconstructs that complete
expected state from the original snapshot. It joins the actual public batch,
selected ID, source/revision, artifact and Prepared result. The new receipt has
the next sequence, the same before/after package digest, the exact group-001
operation and deterministic staging/backup paths from its hash. The whole old
receipt prefix and every other state value must remain unchanged; JSON types
also remain distinct. Both update timestamps must be canonical UTC, equal,
nonregressing and inside the actual repair command's measured wall-clock
interval. Only this verified state becomes the dry-run byte baseline.

Package, data, source and Project B snapshots remain equal, alongside the
existing protected-file checks, exact native config bytes and MCP witness
absence. The original false `no_consent_config_and_state_unchanged` evidence
field is replaced by the explicit committed-repair proof and its before/after
state hashes. No new native command, trust grant, timeout or ACP-zero claim is
introduced. The recorded actual Cobra state/DTO pair replays through the new
consumer; that replay uses recorded state timestamps as its interval and does
not claim an originally captured command wall-clock interval.

Local inert validation passes all 25 protocol and 18 no-auth contracts. New
negative cases cover altered receipts/history, identity/revision/data/native
ownership, unrelated state, timestamp drift, typed-value substitution and
changed package/config/foreign files or witness events. Invalid ordinary
repair stops before dry-run and publishes no preview completion evidence.
Current-source genuine native workflows and original-artifact review remain
required; the older generic Project failure and separate User gate are not
superseded by this correction.
