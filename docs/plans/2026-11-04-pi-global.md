## P0: prerequisites и пути

Native root берётся из existing canonical Pi profile resolution: по умолчанию
`~/.pi/agent`, либо реально выбранный `PI_CODING_AGENT_DIR`. Global destinations —
`<profile>/skills/<name>` и `<profile>/mcp.json`; Project остаётся `.pi/skills` и
`.pi/mcp.json`. Не жёстко кодировать HOME и не выдавать project root за user profile.
Подтверждение host capability: [Pi native MCP](https://pi.dev/changelog/releases/0.99.0),
native source `earendil-works/pi/packages/coding-agent/docs/{mcp,skills}.md`.
Переиспользовать pinned release acquisition и native scripted model; не утверждать,
что любое новое Pi version либо vendor login уже квалифицированы.

## Реализация и центральная граница

1. Обобщить существующие component layout/object helpers ровно настолько, чтобы они
   принимали проверенный user или project authority. Корни/receipts каждого scope
   сохраняют exact path/digest; не использовать project-only object kind как ложную user identity.
2. Global Skill/MCP ownership и update/repair/remove идут через existing
   `ProjectComponents`, `ProjectComponentMutation`, nativeconfig kernel и
   `CompleteNativeConfigActivation`; имя helper не требует создания нового framework.
3. Global source/precondition проверяет original canonical profile, selected package/data
   locators и чужие одноимённые entries. Project/native precedence сохраняется;
   Global не обязан побеждать trusted project override. Project trust UAP не выдаёт.
4. Extension-only старые user/project bindings продолжают прежний lifecycle.
   Fresh-process replay ориентируется на recorded scope/native object identity,
   не на то, что новая версия адаптера теперь умеет Skills/MCP. Новая установка без
   extension entrypoint не должна становиться исполняемой Pi extension случайно.
5. Удаление owned Global components не требует Directory network или live Pi.
   Edited-owned/foreign entries защищены текущей conflict policy; data retention не менять.

Atomic request main owner: user Skills/MCP capability и необходимые native-effect/
lifecycle traits включить только вместе с готовым adapter и доказательствами;
сохранить extension support и существующий command withholding. Request может быть
интегрирован отдельно от #707. Native qualification и Local/Git fixture не должны
ждать подписанного Directory v2; catalog authorization/grants выполняет main owner позже.

Central request применяется integrator в ТОТ ЖЕ leaf PR, что и adapter code;
в один проверенный merge result входят реализация и нужные traits. Leaf worker не
редактирует shared/central files параллельно, но они могут входить в его PR через
integrator. Ранний отдельный capability-only commit на main запрещён.

## Минимальные новые проверки

Existing `TestPiProjectNativeSkillsMCPFacadeAAndB` уже проверяет A/B, update, repair,
edited Skill refusal, exact remove и foreign/user preservation. Добавить Global
в тот же fixture, без второй 175-строчной копии. Existing extension tests остаются.

| Недостающая assertion | Lean реализация |
| --- | --- |
| Global components в default/custom profile, independent Project A/B; Global update/remove не меняет их | Scope/profile parameters existing facade fixture |
| Skills-only/MCP-only и old extension receipt repair/remove; foreign/edited refusal и отсутствие случайного extension entrypoint | Небольшая таблица с тем же package builder |
| Genuine Pi Global Skill source и MCP call; HTTP в Global/Project дополнительно к existing project stdio proof | Scope/transport parameter в `pi_project_components_native_e2e.py`, существующий `ScriptedPiModel` и project driver |

Один mixed package содержит один Skill и два инертных сервера stdio/HTTP. Genuine
admitted Pi должен выполнить initialize/list/call в обоих scopes; только list не PASS.
Переиспользовать `pi_project_native_e2e.py` acquisition/PINS и `pi_local_model_fixture.py`;
общий HTTP server helper запрашивается integrator и считается один раз, не копируется.
Новый custom profile assertion имеет смысл только с тем же оригинальным native profile
в UAP и реальном Pi child. Тестовые disposable profiles не меняют production HOME policy.
Нет 30×30, нового model harness, повторной реализации solver/recovery, SaaS OAuth matrix.
