## Acceptance contract

Reproduce real public UAP CLI source acquisition, installation, native outputs, saved dependency/lock state, removal and preservation of unrelated files across the **15 adapters declared in the product**: Codex, ChatGPT, Cursor, GitHub Copilot CLI, VS Code, Kiro, Claude Code, Gemini CLI, OpenCode, Cline, Windsurf/Devin, Grok Build, Kimi Code, Qoder and Pi. An executable client is required where its adapter relies on one; an empty config directory is not evidence that a client was installed.

The frozen input file is [`tests/live-install/fixtures.json`](../../tests/live-install/fixtures.json). It includes **30 different complete Agent Plugins 1.0 packages** (21 eligible signed Registry distributions + 9 independently published root `plugin.json` packages) and **30 standalone Agent Skills 1.0** from four real repositories. Direct Git packages use verified exact 40-hex commits; each Skill uses an exact commit and original `SKILL.md` Git-blob SHA-1. There are no synthetic plugins/Skills or intercepted HTTP responses in the live lanes.

**Definitions:** `passed` requires the correct source/client identity, actual native projection or Skill file, successful removal and unchanged foreign neighbors. `prepared-lifecycle-passed` proves package preparation and safe removal but **not** client activation. `host-containment-unavailable`, `client-unavailable`, `manual-setup-prepared`, `documented-unsupported` and external auth are *not* `passed`. A live model, OAuth or third-party MCP service call is out of scope; no subscription is needed to test installation.

## Why the sample changed

The original raw-source set contained four real but symlink-bearing upstream repositories (SwiftUI Agent Skill, Swift Concurrency Agent Skill, Perplexity Platform, OpenTelemetry Agent Skills). Their acquisition completed, but UAP's strict package staging rejected symlinks. The fifth (`microsoft/rayfin`) correctly failed closed when LintAI returned status 2. Retain these as **negative compatibility/security observations**.

The revised positive acceptance set replaces those five candidates, not their safety policies, with five real GitHub packages whose inspected trees contain no symlinks: `gemini-cli-extensions/sre`, `itential/builder-skills`, `cometchat/cometchat-skills`, `uizze/uizze`, and `workato-devs/recipe-skills`. A clean Git tree is only a *prerequisite*, not a passing install. The nine current direct-source names, commit pins and root manifests are in the fixture. Each still needs a real CLI acceptance result on the final SHA.
