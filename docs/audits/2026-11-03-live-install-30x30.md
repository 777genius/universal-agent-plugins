# Live installation audit: 30 plugins × 30 Skills × supported clients (2026-11-03)

## Objective and evidence boundary

Reproduce the public user's installation path for **30 distinct complete Agent Plugins 1.0 packages** and **30 distinct standalone Agent Skills 1.0**, against **every adapter advertised in README**. Test acquisition, real CLI installation, persistent/native output, idempotent replay and safe cleanup. Use isolated profiles and exact source identities. An agent subscription or model run is **not** required to prove installation; however, installation or file preparation is **not** proof of agent startup, OAuth, tool execution or model behavior.

**Status:** initial plan and empty defect log. **Confirmed passed installs: 0 / 30 plugins, 0 / 30 Skills. No defects have yet been reproduced.** Replace these numbers only using actual run artifacts.

## Execution matrix

- Clients: `codex`, `chatgpt`, `cursor`, `copilot`, `vscode`, `kiro`, `claude`, `gemini`, `opencode`, `cline`, `windsurf`, `grok`, `kimi`, `qoder`, `pi`. Confirm exact CLI target IDs before executing.
- Scope: isolated **user** scope for full coverage (reviewed signed-directory aliases are not portable project aliases). Include **project** scope for direct pinned sources on qualified targets as a separate representative regression. ChatGPT project scope is explicitly unsupported. VS Code is frozen per `AGENTS.md`: test existing behavior, no changes to its adapter/fixtures.
- Sources: choose 30 *distinct, inspectable, installable* packages, not 30 aliases for one package. Mix signed registry entries and exact Git sources, different transports/components and less-popular/random candidates. Record exact URI/commit, observed package identity and manifest contents. Never make up selectors to meet the quota.
- Skills: 30 *distinct* Skills, across multiple public GitHub repositories and qualifying HTTPS publishers when possible; record `SKILL.md` source, selector and exact `--skill`. `skills.sh` listing URLs alone are not installable source URLs.
- Per source/target: record detection, command+version, exit code, source digest/identity, required on-disk assets, managed binding, `uap.toml`/`uap.lock` when applicable, `list`/`deps status`, remove and preservation of foreign files. Check a fresh isolated home/project for each run. Do not count cached acquisition alone as installed.
- For each unsupported combination, distinguish documented limitation, unavailable real client, external sign-in, infrastructure failure and reproducible installer defect. **No fake success** for unavailable clients, no `--accept-security-risk` to force a green matrix, no credentials, tokens, third-party service mutations or unreviewed install scripts.
- Freeze input manifest (30+30) and generated `JSON` per-case evidence in CI artifacts; results are not claimed until actual GitHub Actions jobs execute.

## Plan of work

1. **Inventory and plan critique.** Read current CLI target/command contracts, signed directory and existing live E2E harness. Select reproducible public sources; reject untrusted/malicious or unsupported entries. Critique scope/security/observability before implementation.
2. **Live acceptance harness.** Reuse the public CLI, existing GitHub-hosted Actions setup and isolated temp profiles. No mock HTTP, mock installer, synthetic `SKILL.md`, guessed native paths or global user writes. Keep deterministic fixtures, bounded timeouts and per-case evidence; report all cases rather than stop at first failure. Run source sets across all *supported* adapters, splitting workers by target to avoid unnecessary sequential runtime.
3. **Reproduce and triage.** Compare exit status with native filesystem and owned-state evidence. For every confirmed bug record **ID, severity, source, target, CLI SHA/version, exact command, expected/actual, logs, root cause, minimal fix plan and regression** below. Failures due to third-party source/network/auth must be identified separately.
4. **One PR, narrow fixes.** Fix only reproduced installer bugs in their existing module/adapter. No feature flags, wholesale refactors, new APIs, unrelated UX, VS Code changes or release publication. Push immediately after each commit.
5. **Qualification and merge.** Re-run live cases on the final head, existing focused tests and required CI. Two independent review passes (security/data loss; architecture/behavior/regressions), then review comments, fixes and re-runs until all critical/actionable findings are resolved. Merge only after all qualifying checks are green and an honest evidence summary is committed.

## Reviewer checklists

**Review pass A — security and recoverability:** independently challenge false-green assertions, arbitrary source execution, dangerous consent overrides, secret/config leakage, foreign-file modification, native ownership, lock/source identity and cleanup.

**Review pass B — architecture and compatibility:** challenge test-only behavior, duplicated logic, excessive orchestration, target detection assumptions, ignored clients, hidden skips, flaky network assertions, mismatched released-vs-main claims and scope creep.

A documented/expected limitation does not become a product defect solely to fill the defect register. Keep exact GitHub Actions run links and commit SHAs with evidence. Do not mark this audit complete on the basis of a created PR or a syntactically valid workflow.
