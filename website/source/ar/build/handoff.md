# تسليم حزمة إلى مخطّط المثبّت {#hand-a-package-to-the-installer-planner}

يتكون التسليم المفيد من مجلد حزمة معيارية وبيان واضح بما جرى فحصه. يضع المثبّت لدى المستلم خطته الخاصة للوكلاء والنطاق المختارين. يمكن لأدوات التأليف المبنية من المصدر تقديم أدلة، لكنها ليست مطلوبة على آلة المستلم.

## جهّز الحزمة والأدلة {#prepare-the-package-and-evidence}

اختر المجلد الذي يحتوي على `plugin.json` في جذره بدل مستودع أب ملتبس. أدرج:

- هوية الحزمة وإصدارها ومراجعة المصدر الدقيقة أو اللقطة التي تمت مراجعتها.
- جذر الحزمة النسبي والغرض من Skills وخوادم MCP فيها.
- نتائج التحقق والفحص مع إصدار الأداة أو مراجعة المصدر.
- معرّفات العملاء المقصودين ونتائج التوافق الخاصة بكل مكوّن.
- متطلبات التشغيل والمصادقة والأعمال التي لم تُقيّم بعد.
- أي اختبار تشغيل صريح، مع الخادم أو الأداة المختارين والمنصة.

يصف إصدار الحزمة وإصدار CLI شيئين مختلفين؛ أبقهما منفصلين. تجنب بيانات الاعتماد والمسارات المطلقة غير الضرورية في التشخيصات المشتركة.

## أكمل فحوص التأليف من المصدر عند توفرها {#finish-source-authoring-checks-when-available}

تتطلب هذه الأوامر الاختيارية [بناء المصدر الداعم للتأليف](./#build-from-source)، وهو منفصل عن إصدار المثبّت الحالي:

```bash
agentplugins author validate ./review-helper
agentplugins author inspect ./review-helper
agentplugins author test ./review-helper
agentplugins author compat ./review-helper --target codex
agentplugins author doctor ./review-helper
```

هذا التسلسل ساكن، ولا يشغّل كود الحزمة أو يفحص ملف تعريف عميل لمستخدم حقيقي. سجّل [فحوص تشغيل MCP](./checks) الصريحة منفصلةً إن أُجريت. وحتى نجاح فحص تشغيل مباشر لا يثبت اكتشاف العميل الأصلي أو OAuth.

## اطلب من المثبّت المنشور إعداد خطة {#ask-the-released-installer-to-plan}

```bash
agentplugins validate ./review-helper
agentplugins add ./review-helper --target codex --dry-run
```

يمكن للمثبّت جلب بيانات أمان وصفية أو ماسحه المثبت الإصدار حتى لمصدر محلي. ليس تحققه وتشغيله التجريبي هما فحوص التأليف غير المتصلة بالشبكة.

يوفر الأمر الأول دليل قراءة الحزمة لدى المثبّت. ويختار الثاني Codex ويعاين التثبيت دون تطبيق تغييرات مُدارة. لعميل آخر، اختر هدفًا مدعومًا وفق نتائج التوافق. ولخطة مشروع، أضف `--scope project --project-root /path/to/project` صراحةً.

افحص هوية الحزمة والمصدر والوجهات والنتائج الأمنية ومتطلبات التفعيل المتبقية. عالج الاختلافات عن التسليم الذي قصده المؤلف قبل التطبيق. الخطة ليست إيصالًا بحالة مثبتة.

## شارك مصدرًا قابلًا لإعادة الإنتاج {#share-a-reproducible-source}

للتوزيع البعيد، استخدم مصدرًا تقبله نسخة CLI لدى المستلم: حزمة Directory موقّعة، أو مصدر GitHub دقيقًا، أو مصدر Git أو أرشيف مباشرًا مدعومًا. راجع [مصادر التثبيت](../use/install) للصيغة والتوفر. استخدم مراجعة غير قابلة للتغيير أو أرشيفًا ثابتًا بإصدار محدد عندما تحتاج إلى استعادة دقيقة. ويحتاج المجلد المحلي إلى نقل منفصل ومقصود.

لا تتيح CLI الخاصة بالتأليف من المصدر أمرًا لنشر الحزم أو تصدير حزمة مجمّعة أو الإرسال إلى Directory. استضافة المصدر خطوة منفصلة عن التحقق منه. إعلانات الاعتماديات في `uap.toml` هي عقد خاص بمدير UAP؛ ويظل `plugin.json` في الجذر المرجع المعتمد لهوية الحزمة القابلة للنقل.

## اشرح ما تبقى {#explain-what-remains}

| الدليل المقدّم | العمل المتبقي |
| --- | --- |
| المطابقة المعيارية | تعليمات مفيدة وسلوك صحيح للأدوات. |
| فحوص التأليف الساكنة | الموافقة على الإصدار وتأهيل القنوات العامة. |
| التوافق الساكن مع العملاء | الاكتشاف والتفعيل الفعليان داخل العميل الأصلي. |
| فحص تشغيل MCP مباشر، إن أُجري | الأدوات والعملاء والمصادقة والبيئات الأخرى غير المختبرة. |
| تشغيل المثبّت التجريبي | تطبيق التغييرات التي روجعت وإكمال إعداد العميل. |

يمكن للمستلم المتابعة إلى [استخدام الإضافات](../use/install) عندما يصبح جاهزًا للتثبيت. احتفظ بتعليمات الثقة والتفعيل الخاصة بالعميل مع الحزمة.
