# Найти и установить плагин

Выбирайте пакет с понятным источником и назначением. Ниже используются команды
опубликованного установщика. Если `agentplugins` ещё не доступен, начните с
[установки CLI](./). Перед применением проверьте план через `--dry-run`.

## Найдите пакет

```bash
agentplugins search docs
agentplugins info context7
```

Короткое имя вроде `context7` выбирает запись из подписанного Universal Agent
Plugins Registry. Поиск и сведения о пакете помогают выбрать вариант, но не
запускают его и не подтверждают доступность сервиса. Изучите инструменты, Skills,
требования к среде исполнения и доступу к учётной записи.

## Проверьте явный выбор клиентов

```bash
agentplugins add context7 --target codex,cursor --dry-run
```

Проверьте источник, выбранные клиенты, пути, результаты проверки безопасности и
оставшуюся активацию. Команда выводит план без применения установки и не
проверяет работу MCP-сервера.

## Примените проверенный план

```bash
agentplugins add context7 --target codex,cursor
```

Для интерактивного выбора опустите `--target`. CLI может автоматически выбрать
единственный обнаруженный агент или показать список при наличии нескольких.
В автоматизации и для воспроизводимого выбора указывайте клиенты явно.

Установщик выполняет предварительные проверки клиентов и защищает файлы, которыми
не владеет. При ошибке отката или незавершённом восстановлении сохраните отчёт
и выполните указания восстановления перед повторной попыткой.

## Завершите активацию

Следуйте результату для каждого клиента: могут требоваться перезапуск, новый
сеанс, доверие к проекту, вход или явная активация. Подготовленные файлы и
успешная регистрация не доказывают OAuth или вызов инструментов. Для отсутствующей
или изменённой установки используйте [диагностику состояния](./manage); если
пакет уже присутствует, проверьте аутентификацию в клиенте.

## Используйте локальный пакет

Выберите каталог с корневым `plugin.json`:

```bash
agentplugins validate ./my-plugin
agentplugins add ./my-plugin --target codex --dry-run
```

Установщик применяет политику безопасности и при проверке или планировании
локального пакета. Ему могут понадобиться загрузка данных безопасности или
закреплённого сканера. `--dry-run` исключает применение управляемой установки,
но не обещает работу без сети.

После проверки плана опустите `--dry-run`. Локальный каталог не становится
переносимой зависимостью, которую другой компьютер сможет получить по сети.
Запросите у автора [сведения о проверках пакета](../build/handoff).

## Выберите точный источник GitHub

В традиционной неизменяемой форме GitHub нужен полный SHA коммита из 40 символов.
Замените пример реальным репозиторием, проверенной ревизией и путём:

```text
agentplugins add owner/repository@0123456789abcdef0123456789abcdef01234567//path/to/plugin --target codex --dry-run
```

Эта форма `owner/repository@...` не принимает ветки, теги или сокращённый SHA.
Без пути выбирается корректный корневой пакет или единственный вложенный
кандидат. При нескольких кандидатах нужен явный путь; при более чем 16 возможных
пакетах путь требуется до их загрузки. Repair воспроизводит записанный источник.
Переход на другую неизменяемую ревизию — отдельное решение о смене источника.

CLI 0.1.93 также принимает прямой Git по HTTPS, SSH, поддерживаемые URL страниц
провайдеров и полные пакеты в HTTPS- или локальных архивах. Замените адреса
примера проверенными источниками:

```text
agentplugins add 'https://git.example.com/team/tools.git#refs/heads/main//plugins/demo' --target codex --dry-run
agentplugins add 'ssh://git@git.example.com/team/tools.git#main//plugins/demo' --target codex --dry-run
agentplugins add 'https://downloads.example.com/plugin.tar.gz' --target codex --dry-run
```

Git использует существующие нативные учётные данные и доверие к SSH-хосту.
HTTPS-архивы загружаются без учётных данных и должны содержать полный стандартный
пакет. Lock-файл фиксирует точный коммит Git или исходные байты архива, а также
хеши пакета. Подвижный источник обновляется явной операцией; восстановление по
lock-файлу сохраняет закреплённую версию. Получение полного пакета отличается от
получения отдельного Skill. Синтаксис провайдеров, выбор пакета, контрольные суммы
и ограничения распаковки см. в
[прямых источниках пакетов](https://github.com/777genius/universal-agent-plugins/blob/main/docs/DIRECT_PACKAGE_SOURCES.md).

## Установите Agent Skills

Группа `skills` работает с отдельными Skills из публичного GitHub-репозитория,
папки, URL `SKILL.md` или HTTPS-источника с полным индексом `.well-known`:

```bash
agentplugins skills add owner/repository --ui
```

Замените `owner/repository` реальным источником. `--ui` открывает встроенный
выбор в браузере и требует интерактивный терминал. Для выбора в терминале
используйте `--no-ui`. Явный выбор:

```bash
agentplugins skills add owner/repository --skill review --skill pdf \
  --target codex,claude --no-ui --yes
```

- Повторяйте `--skill` для точных имён. При неоднозначности используйте `--path`
  с точным путём к папке Skill относительно репозитория.
- `--ref` выбирает точный Git ref при неоднозначной границе URL.
- `--dry-run` показывает план без установки.
- Для JSON и неинтерактивного режима нужны явные Skills, клиенты и `--yes`,
  кроме предварительного просмотра с `--dry-run`.
- `--ui` несовместим с `--skill`, `--target` и `--dry-run`.
- HTTPS-источнику нужен точный `--skill`, а его индекс должен перечислять все
  файлы Skill.

Автоматические результаты проверки безопасности могут блокировать установку.
`--security-details` показывает подробности в человекочитаемом выводе. Изучите
их до решения о явном `--accept-security-risk`. Установленные Skills видны в
`agentplugins list` и обслуживаются обычными командами.

## Установите для одного проекта

Явная область проекта доступна в
[CLI 0.1.93 и новее](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.93).
Выберите существующую папку и указывайте область в каждой команде:

```bash
agentplugins add context7 --target cursor --scope project \
  --project-root /path/to/project --dry-run
agentplugins skills add owner/repository --ui --scope project \
  --project-root /path/to/project
```

Первая команда показывает план; для применения опустите `--dry-run`. Вторая
открывает выбор с областью проекта и может применить выбор пользователя.
Без `--project-root` явная область проекта использует текущую папку, не ищет
родительские каталоги. Добавление и обслуживание в остальных случаях используют
пользовательскую область. В CLI 0.1.94 `install` без аргумента источника выбирает проект
при обычном `uap.toml` непосредственно в текущей папке; явная область имеет приоритет.
Правила строгой работы с lock-файлом см. в [восстановлении](./manage).

Клиент должен поддерживать запрошенные проектные компоненты. Установка в проект
ChatGPT явно не поддерживается. VS Code подготавливает `.github/skills` и
принадлежащие установщику записи `servers` в `.vscode/mcp.json` для одной
локальной папки. Результат остаётся Prepared: проверьте доверие к рабочей папке,
серверам и настройки клиента. Наблюдение метаданных не доказывает запуск MCP,
вызов инструментов или работу модели.

См. [установку в проект](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_INSTALLATION.md)
и [границы каждого клиента](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_CLIENT_SUPPORT.md).
Далее — [обслуживание и восстановление](./manage).
