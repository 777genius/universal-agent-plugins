# Использовать плагины

Universal Agent Plugins устанавливает стандартные пакеты для выбранных
ИИ-агентов. Пакет может содержать Skills, конфигурацию MCP-серверов или оба
компонента. Установка может относиться к вашей учётной записи или отдельному
проекту.

## Установите CLI

При наличии Node.js 22 или новее можно запускать npm-обёртку напрямую:

```bash
npx universal-agent-plugins search docs
```

Для регулярной работы установите её глобально:

```bash
npm install -g universal-agent-plugins
agentplugins version
```

Также доступен Homebrew:

```bash
brew install 777genius/agentplugins/agentplugins
```

[Инструкция по нативной установке](https://github.com/777genius/universal-agent-plugins/blob/main/docs/NATIVE_INSTALL.md)
описывает macOS, Linux и Windows. Самому нативному менеджеру Node.js не нужен,
но отдельным плагинам может требоваться собственная среда исполнения. В примерах
используется `agentplugins`; те же команды установщика можно запускать через
`npx universal-agent-plugins`.

## Пройдите путь установки

1. [Найдите и изучите пакет](./install), его источник и требования.
2. Проверьте план для нужных клиентов и области установки с `--dry-run`.
3. Примените проверенный план и выполните указания по активации.
4. [Обслуживайте установленное состояние](./manage): просмотр, обновление, восстановление и удаление.
5. При необходимости восстановите набор зависимостей по `uap.toml` и `uap.lock`.

[CLI 0.1.95](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.95)
— текущий нативный установщик. Он добавляет локальный API управления и нативные
расширения Pi в пользовательской области. Подробнее:
[локальное управление](./manage#local-management-api) и
[совместимость с Pi](../reference/client-compatibility#pi-native-extensions).
Пакетные каналы могут обновляться позднее: проверьте `agentplugins version`.
Проверенный текущий выпуск доступен через нативный установщик.

Явная проектная область работает с 0.1.93. Большинство команд используют
пользовательское окружение. Начиная с 0.1.94, `install` без аргумента источника
и явной области выбирает проект только при обычном файле `uap.toml`
непосредственно в текущей папке, без поиска родителей. В командах обслуживания
указывайте `--scope project`. Поддерживаемые компоненты и активация зависят
от клиента.

## Читайте результат на нужном уровне

После установки могут оставаться перезапуск, доверие к проекту, ручная активация
или OAuth. Состояние Prepared означает, что необходимы дополнительные действия
в клиенте. Изучайте результат каждого целевого клиента. Обоснование конкретных
наблюдений см. в [совместимости клиентов](../reference/client-compatibility).

## Если вы создаёте пакет

Начните с [руководства по созданию](../build/). Результат передаётся как каталог
с корневым `plugin.json` и компонентами. Получателю не требуется запускать
средства разработки из исходного кода.

| Команда | Назначение |
| --- | --- |
| `agentplugins validate ./my-plugin` | Прочитать и проверить локальный пакет перед установкой. |
| `agentplugins doctor` | Проверить состояние, которым управляет установщик. |
| `agentplugins author validate ./my-plugin` | Проверить соответствие и готовность пакета в сборке со средствами разработки. |
| `agentplugins author doctor ./my-plugin` | Изучить сведения о проекте и инструментах в такой сборке. |

В текущем npm- и нативном выпуске установщика нет `agentplugins author`.
