# Обслуживать установленные плагины

Команды установщика проверяют и изменяют управляемое состояние. При разборе
проблем сохраняйте источник пакета, клиенты, область и идентификатор установки.
Примеры используют пользовательскую область, если проект не выбран явно.

## Сначала изучите состояние

```bash
agentplugins list
agentplugins doctor
agentplugins outdated --all
```

`list` перечисляет установки, `doctor` проверяет управляемое состояние,
`outdated` ищет обновления без их применения. Они не доказывают доступность
удалённого сервиса или завершённую аутентификацию клиента.

| Проблема | Следующий шаг |
| --- | --- |
| Пакета нет | [Найти и установить](./install). |
| Управляемые файлы исчезли или изменились | Проверить план repair для пакета и нужной области. |
| В отслеживаемом источнике есть новая версия | Проверить план update. |
| Клиенту нужны доверие, активация или вход | Выполнить указанные клиентом действия. |
| Локальный пакет не проходит проверку | Передать автору отчёт и [руководство по проверкам](../build/checks). |

## Обновляйте осознанно

```bash
agentplugins update context7 --target codex,cursor --dry-run
```

Проверьте источник, версию и пути. Для применения опустите `--dry-run`:

```bash
agentplugins update context7 --target codex,cursor
```

`update --all` охватывает все управляемые кандидаты обновления. Используйте его,
когда нужен весь этот набор. Точный коммит остаётся неизменяемым: обновление не
превращает его в отслеживание ветки. Диапазоны и подвижные refs сохранённых
зависимостей продвигаются соответствующей явной операцией update.

## Восстановите записанное состояние

```bash
agentplugins repair context7 --target codex,cursor --dry-run
agentplugins repair context7 --target codex,cursor
```

Первая команда показывает план, вторая применяет его. Repair использует
записанный источник для восстановления управляемого содержимого. Он не выбирает
новую ревизию и не перезаписывает незаметно изменённые извне нативные записи.
Изучите конфликты и указания по незавершённому восстановлению.

## Удалите выбранную установку

```bash
agentplugins remove context7 --target codex,cursor --dry-run
agentplugins remove context7 --target codex,cursor
```

Прочитайте первый план перед второй командой. Удаление использует записанные
границы владения CLI; оно не отзывает доступ к сервису, не удаляет сторонние
среды исполнения и исходный каталог автора. Удаление из проекта по умолчанию
сохраняет данные плагина и общий проверенный кэш содержимого.

## Используйте сохранённое окружение зависимостей

`uap.toml` задаёт требуемые пакеты и клиенты; `uap.lock` фиксирует точные
источники и хеши. Проверьте выбранное окружение:

```bash
agentplugins deps status
agentplugins deps tree
```

Для нового окружения выполните `agentplugins deps init`, осознанно отредактируйте
манифест, разрешите зависимости через `agentplugins deps lock` и примените lock
через `agentplugins install --locked`. Изучайте подтверждения; для просмотра
есть `--dry-run`. [Руководство по зависимостям](https://github.com/777genius/universal-agent-plugins/blob/main/docs/UAP_DEPENDENCIES.md)
объясняет синтаксис, обязательные зависимости пакетов, диапазоны и обновления.

Ранее выполненная установка не обязательно входит в переносимое соглашение.
Проверьте `deps status` и сами файлы до переноса. Автоматическое сохранение
обычных удалённых `add` описано отдельно для исходного кода; квитанция об
установке сама по себе его не доказывает.

## Восстановите на другом компьютере

В папке для переноса на исходном компьютере выполните:

```bash
agentplugins deps export
```

Скопируйте папку на другой компьютер, установите нужные клиенты и выполните там:

```bash
agentplugins deps import
agentplugins install --locked --scope user
```

Либо совместите импорт и восстановление:

```bash
agentplugins deps import --install
```

Необязательный аргумент каталога выбирает другую папку обмена. Export читает
пользовательское окружение, import записывает его; `AGENTPLUGINS_HOME` может
выбрать конкретное окружение. Переданная папка не заменяет профиль клиента.
Явный `--scope user` сохраняет пользовательскую область восстановления.

Переносятся только неизменённые, строго проверенные `uap.toml` и `uap.lock`.
Фактическое копирование показывает план и требует подтверждения или `--yes`;
`--dry-run` показывает его без записи. Импорт проверяется без сети, но установке
нужны записанные источники или проверенный кэш. При пустом кэше загружаются
точные закреплённые пакеты с проверкой хешей, без выбора новых версий.

Профили, настройки, учётные данные, квитанции и `PLUGIN_DATA` не переносятся.
Настройте вход на новом компьютере, отдельно сохраните данные плагинов. Если
установка не удалась после сохранения пары при импорте, исправьте причину и
повторите `install --locked --scope user`. При сообщении о незавершённом
восстановлении сначала выполните `deps recover --scope user`. Не пересоздавайте
перенесённые закрепления через `deps lock`: подвижный источник может разрешиться
иначе.

## Восстановите и обслуживайте проект

Явная область проекта доступна в
[CLI 0.1.93 и новее](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.93).
Добавьте проектные `uap.toml` и `uap.lock` в контроль версий. В другом существующем
checkout установите нужные клиенты и выполните:

```bash
agentplugins install --locked --scope project --project-root /path/to/project
```

Для обслуживания выбирайте ту же область и корень:

```bash
agentplugins list --scope project --project-root /path/to/project
agentplugins deps status --scope project --project-root /path/to/project
agentplugins repair review --target cursor --scope project --project-root /path/to/project
agentplugins deps recover --scope project --project-root /path/to/project
```

При неоднозначном имени используйте идентификатор из `list`. Опубликованный CLI
по умолчанию использует пользовательскую область: наличие проектного манифеста
не меняет её. `--scope project` без `--project-root` выбирает текущую папку.

Квитанции, журналы восстановления и сохранённые данные `.uap/` оставляйте
локальными. Нативные компоненты восстанавливайте по переносимой паре файлов,
после чего выполните требования клиента к доверию и активации. Источники и
доступ к закрытым репозиториям должны оставаться доступны. См.
[установку в проект](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_INSTALLATION.md)
и [ограничения клиентов](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_CLIENT_SUPPORT.md).

## Удобство в текущем исходном коде

**Только исходный код, ещё не выпущено:** `agentplugins install` без аргумента
источника выбирает проектную область при обычном файле `uap.toml` в точной
текущей папке, без поиска родителей. Явная область имеет приоритет. Существующий
lock строго проверяется до изменений; первоначальное разрешение возможно только
при его отсутствии. `--locked` требует lock-файл. В опубликованном CLI выбирайте
проект явно и используйте `--locked`.

## Как сообщить о проблеме

Запишите версию CLI, команду, область, источник пакета, клиенты и оставшуюся
активацию. Укажите этап: получение источника, планирование, запись файлов,
восстановление, обнаружение клиентом, аутентификация или исполнение. Удалите
секреты из диагностики. `author doctor ./my-plugin` изучает исходный пакет;
`agentplugins doctor` проверяет состояние установщика.
