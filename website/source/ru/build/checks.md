# Проверить пакет и результаты

**Средства из исходного кода:** команды `agentplugins author` требуют
[соответствующей сборки](./#build-from-source). В текущем установщике их нет.
Запускайте относительные примеры из родительской папки пакета и каждый раз
выбирайте один точный корень.

## Выполните статический цикл без сети

```bash
agentplugins author validate ./review-helper
agentplugins author inspect ./review-helper
agentplugins author test ./review-helper
```

Validate проверяет стандартную конфигурацию и готовность пакета. Inspect
показывает компоненты и недостающие требования. `test` без параметров исполнения
статически проверяет конфигурацию, гигиену, Skills и MCP. Эти команды не запускают
серверы и не исполняют инструкции Skill.

## Читайте уровни отдельно

| Уровень | Что подтверждает | Что требует отдельной проверки |
| --- | --- | --- |
| Соответствие | Сохранённые стандартные данные соответствуют встроенной схеме и профилю. | Полезное поведение в конкретном агенте. |
| Безопасность хоста | Входные данные проходят ограниченные проверки путей и хоста. | Разрешение пользователя на установку и запуск. |
| Готовность | Доступные сведения удовлетворяют проверяемой политике. | Одобрение публичного выпуска и принятие платформой. |
| Совместимость | Статическую поддержку выбранных компонентов и клиентов. | Реальное обнаружение и активацию в клиенте. |
| Инструменты | Ограниченные сведения о проекте, нативных и исполняемых файлах. | Получение зависимостей и успешный запуск. |
| Исполнение | Явно выполненная MCP-проверка показывает наблюдённые этапы. | Другие инструменты, клиенты, OAuth и непроверенные окружения. |

Соответствие схеме и общая готовность — отдельные результаты. Корректный манифест
может сочетаться с неполными данными о компонентах или хосте. Сохраняйте
«не проверено» вместо превращения этого состояния в успех.

## Явно выберите клиенты

```bash
agentplugins author compat ./review-helper --target codex,claude
agentplugins author inspect ./review-helper --target codex,claude
agentplugins author doctor ./review-helper
agentplugins author capabilities
```

`compat` принимает разные ID через запятую, но не `all`. Статические проверки
не требуют установленных клиентов. Doctor читает ограниченные нативные данные
и метаданные исполняемых файлов без процессов и сети. Capabilities описывает
схемы, метаданные клиентов и команды данной сборки. Это не сертификация пакета
и не доказательство публичного выпуска.

## Явно проверьте исполнение MCP {#evaluate-mcp-runtime-explicitly}

Локальное исполнение stdio сейчас требует Linux, системный bubblewrap и Node
в системных каталогах. До запуска должны пройти проверки изоляции процессов
(включая делегированную cgroup v2) и пространств имён bubblewrap.
Подробнее — в [требованиях stdio](./mcp-stdio). Streamable HTTP не использует
эту изоляцию локального процесса, но требует явного разрешения сети.

Для пакета из [руководства stdio](./mcp-stdio) отдельно установите распознанные
зависимости по lock-файлу, затем выберите точное имя сервера из `mcp.json`:

```bash
agentplugins author test ./local-tools --runtime mcp --server local-tools
```

Команда запускает выбранный процесс и проверяет инициализацию и список
инструментов. Для вызова нужны одновременно `--tool` и `--fixture`. Fixture —
путь относительно пакета к JSON-объекту с аргументами инструмента. Для шаблонного
`hello` создайте `fixtures/hello.json` с содержимым `{}`:

```bash
agentplugins author test ./local-tools --runtime mcp --server local-tools \
  --tool hello --fixture fixtures/hello.json
```

Для Streamable HTTP явно разрешите сеть:

```bash
agentplugins author test ./docs-service --runtime mcp --server docs-service \
  --allow-network
```

Используйте реальное имя сервера из пакета. Срок проверки по умолчанию — десять
секунд; `--deadline` задаёт положительную длительность не более минуты. Читайте
инициализацию, обнаружение инструментов, необязательный вызов и завершение
раздельно. Такой результат не является запуском через установленный агент и
не доказывает OAuth, другие инструменты или публичное развёртывание.

## Повторяйте цикл разработки

```bash
agentplugins author dev ./local-tools --server local-tools
```

`dev` выполняет ограниченные MCP-циклы при изменении пакета; для остановки
используйте Ctrl+C. `--once` выполняет один цикл и обязателен для JSON-вывода.
Удалённому серверу нужен `--allow-network`; вызову инструмента — явная пара
имени и fixture. Команда не устанавливает пакет в нативный клиент.

## Сохраните проверяемый отчёт

```bash
agentplugins author validate ./review-helper --format json
agentplugins author inspect ./review-helper --format json
```

Для обычного вывода есть `--format human`, для отключения цвета — `--no-color`.
`--include-root` раскрывает выбранный корень: не передавайте ненужные закрытые
пути. `--release-policy` добавляет ограниченные проверки качества выпуска,
но не даёт разрешение на публикацию. У Skills меньше параметров; изучайте
справку конкретной подкоманды.

## Осознанно изменяйте JSON

Текущий исходный код планирует детерминированную нормализацию одного стандартного
файла и записывает его только с `--write`:

```bash
agentplugins author normalize ./review-helper --document plugin.json
agentplugins author normalize ./review-helper --document plugin.json --write
```

Выберите `mcp.json`, если нужен именно он. Нативный импорт читает один явно
указанный строгий JSON-файл Claude MCP, без поиска профилей. Импортируются
только безопасные stdio-записи с `command` и необязательным `args`. HTTP/URL,
`env` и дополнительные поля сервера пропускаются, даже если исходный клиент
их принимает. Сначала проверьте
план для нового отсутствующего абсолютного пути:

```bash
agentplugins author import native ./claude.json --from claude \
  --output /absolute/path/to/new-plugin --name new-plugin \
  --description 'Импортированный пакет Claude MCP'
```

Изучите безопасные и пропущенные серверы, неподдерживаемые поля. Добавьте
`--write`, чтобы сохранить проверенный пакет в новом месте. Небезопасные
серверы и записи с учётными данными пропускаются; не предполагается перенос
каждого исходного сервера. Импорт других клиентов здесь не предоставляется.

## Соблюдайте границы команд

`agentplugins validate ./review-helper` читает пакет для установщика;
`agentplugins doctor` проверяет управляемое установленное состояние. Это
отдельные задачи. Область и параметры безопасности установщика не становятся
параметрами author. Init создаёт реальные файлы; normalize и import применяют
план только с `--write`. Далее — [передача пакета](./handoff).
