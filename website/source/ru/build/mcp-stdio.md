# Создать MCP-пакет со stdio

**Средства из исходного кода:** команды ниже требуют
[соответствующей сборки](./#build-from-source). В текущем установщике их нет.

Выберите stdio, если пакет поставляет локальный процесс, обменивающийся данными
через стандартный ввод и вывод. Шаблон поддерживает Node.js 22 или новее и
официальный MCP SDK. Создание файлов не устанавливает зависимости и не запускает
сервер.

## Создайте шаблон

Выберите отсутствующий каталог под существующим родителем:

```bash
agentplugins author init ./local-tools \
  --template mcp-stdio \
  --name local-tools \
  --description 'Локальные инструменты через Node MCP-сервер' \
  --runtime node
```

Для этого переносимого шаблона поддерживается `node`. Параметры среды Python
или Go не входят в текущий контракт команды.

## Изучите файлы

```text
local-tools/
  plugin.json
  mcp.json
  package.json
  package-lock.json
  src/
    server.mjs
  README.md
  .gitignore
```

`mcp.json` объявляет сервер `local-tools`, команду `node` и аргумент
`${PLUGIN_ROOT}/src/server.mjs`. Подстановка указывает внутрь выбранного пакета,
а не в текущую папку оболочки. Исходный код содержит небольшой инструмент
`hello`. Измените его под свою задачу. Пишите журналы приложения в stderr,
сохраняя stdout для протокола MCP.

Изучите манифест зависимостей и lock-файл. Init их записывает, но не запускает
npm и не подтверждает возможность импортировать SDK на этой машине.

## Соберите статические результаты

```bash
agentplugins author validate ./local-tools
agentplugins author inspect ./local-tools
agentplugins author test ./local-tools
agentplugins author compat ./local-tools --target codex,claude
agentplugins author doctor ./local-tools
```

Это статические проверки. Doctor изучает ограниченные сведения о проекте и
исполняемых файлах. Он не подтверждает установку зависимостей, рукопожатие MCP
или вызов инструмента. Читайте [уровни доказательств](./checks) раздельно.

## Установите зависимости распознанного шаблона

Для созданной структуры Node с соответствующим lock-файлом текущий исходный код
может показать и выполнить установку зависимостей:

```bash
agentplugins author bootstrap ./local-tools --dry-run
agentplugins author bootstrap ./local-tools
```

Применение bootstrap сейчас требует Linux и поддержки операций с каталогом
через открытый файловый дескриптор. Другие платформы возвращают
`bootstrap_platform_unsupported`. Предварительный просмотр может проверить
распознанную структуру без установки зависимостей.

Проверьте план перед применением. Bootstrap выполняет npm-установку по lock-файлу
с отключёнными lifecycle-скриптами. Он принимает распознанную структуру шаблона,
соответствующие package-файлы и отсутствующий `node_modules`. Это не замена
произвольного пакетного менеджера. Изменённые зависимости, конкурирующие
lock-файлы или существующий результат могут вызвать отказ. Исправьте указанную
причину вместо поиска флага перезаписи. Получение зависимостей может
использовать сеть.

## Выполните явную проверку MCP

Локальный stdio сейчас требует Linux, системный `bwrap` (bubblewrap), рабочую
изоляцию процессов с делегированной группой cgroup v2, поддержку пространств
имён и Node внутри системных каталогов `/usr`, `/bin`,
`/lib` или `/lib64`. Команда требует успешных проверок изоляции процессов и bubblewrap до запуска
кода и отказывает,
если установить её не удаётся. Node в пользовательском каталоге менеджера
версий не соответствует этому контракту. Статические проверки доступны отдельно.

```bash
agentplugins author test ./local-tools --runtime mcp --server local-tools
```

Команда запускает выбранный локальный процесс, проверяет инициализацию MCP и
обнаружение инструментов. Для вызова `hello` нужен явный JSON-файл аргументов;
см. [пример проверки исполнения](./checks). Для повторяемой разработки:

```bash
agentplugins author dev ./local-tools --server local-tools
```

Сохраняйте точные версии средств, пакета и платформы вместе с результатом.
Прямая проверка не доказывает работу через любой нативный агент и не
подтверждает доверие или аутентификацию клиента.

## Подготовьте передачу

Опишите инструменты, требование Node.js, файлы зависимостей и результаты запуска
в README. Укажите сервер и непроверенные инструменты или окружения. Затем
используйте [передачу установщику](./handoff). Если к инструментам нужны
инструкции, добавьте [Skills](./skills).
