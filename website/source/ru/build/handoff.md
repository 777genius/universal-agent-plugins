# Передать пакет установщику

Полезный результат передачи — стандартный каталог пакета и ясное описание
проведённых проверок. Установщик получателя строит отдельный план для выбранных
клиентов и области. Средства разработки из исходного кода могут дать результаты,
но получателю не требуется устанавливать их.

## Подготовьте пакет и сведения

Выберите каталог с корневым `plugin.json`, а не неоднозначный родительский
репозиторий. Приложите:

- Идентичность, версию, точную ревизию исходного кода или проверенный снимок.
- Относительный корень пакета и назначение его Skills и MCP-серверов.
- Результаты validate и inspect с версией инструмента или commit сборки.
- Предназначенные клиенты и совместимость отдельных компонентов.
- Требования к исполнению, аутентификации и непроведённые проверки.
- Результат явного запуска MCP, если он был, с выбранными сервером, инструментом и платформой.

Версия пакета и версия CLI — разные значения. Не включайте секреты и ненужные
абсолютные пути в передаваемые отчёты.

## Завершите доступные проверки исходного пакета

Эти необязательные команды требуют [сборки со средствами разработки](./#build-from-source),
которая отличается от текущего опубликованного установщика:

```bash
agentplugins author validate ./review-helper
agentplugins author inspect ./review-helper
agentplugins author test ./review-helper
agentplugins author compat ./review-helper --target codex
agentplugins author doctor ./review-helper
```

Последовательность статическая: она не запускает код пакета и не изучает
настоящий пользовательский профиль клиента. [Явные проверки исполнения MCP](./checks)
записывайте отдельно. Их успех также не устанавливает обнаружение в клиенте
или OAuth.

## Попросите опубликованный установщик построить план

```bash
agentplugins validate ./review-helper
agentplugins add ./review-helper --target codex --dry-run
```

Установщик может загружать сведения безопасности или закреплённый сканер даже
для локального пакета. Его validate и dry-run не являются статическими
проверками author без сети.

Первая команда проверяет чтение пакета установщиком. Вторая выбирает Codex и
показывает изменения без применения. Для другого клиента используйте
поддерживаемую цель из результатов совместимости. Для проектного плана добавьте
`--scope project --project-root /path/to/project`.

Проверьте идентичность, источник, пути, результаты безопасности и оставшуюся
активацию. Устраните расхождения с намерениями автора до применения. План не
является квитанцией о выполненной установке.

## Передайте воспроизводимый источник

Используйте источник, который принимает CLI получателя: подписанную запись
Directory, точный GitHub-источник или поддерживаемый прямой Git/архив.
Синтаксис и доступность см. в [установке](../use/install). Для точного
восстановления выбирайте неизменяемый commit или долговечный версионированный
архив. Локальный каталог требует отдельного осознанного переноса.

Средства разработки не предоставляют команды публикации пакета, экспорта
архива или отправки в Directory. Размещение исходников отдельно от их проверки.
Зависимости в `uap.toml` — контракт менеджера UAP; корневой `plugin.json`
остаётся источником идентичности переносимого пакета.

## Объясните оставшиеся действия

| Переданный результат | Что остаётся |
| --- | --- |
| Соответствие стандарту | Полезные инструкции и корректное поведение инструментов. |
| Статические проверки разработки | Одобрение выпуска и проверка публичных каналов. |
| Статическая совместимость | Реальное обнаружение и активация в клиенте. |
| Прямая проверка MCP, если выполнена | Другие инструменты, клиенты, вход и непроверенные окружения. |
| План установщика | Применение изменений и завершение настройки клиента. |

Получатель может перейти к [установке](../use/install), когда готов применить
пакет. Сохраняйте указания доверия и активации вместе с ним.
