# Создать пакет удалённого MCP

**Средства из исходного кода:** команды требуют
[соответствующей сборки](./#build-from-source). В текущем установщике нет
`agentplugins author`.

Выберите удалённый MCP, когда сервер уже существует, а пакет описывает подключение
агента к нему. При создании пакета URL сохраняется без обращения к серверу.
Уточните транспорт и требования к аутентификации до передачи пользователям.

## Укажите адрес явно

`https://mcp.example.com/mcp` ниже — пример. Замените его реальной конечной точкой.
Команда не проверяет, что адрес обслуживает MCP и ваша учётная запись имеет доступ.

```bash
agentplugins author init ./docs-service \
  --template mcp-remote \
  --name docs-service \
  --description 'Подключение к MCP-сервису командной документации' \
  --url https://mcp.example.com/mcp
```

Выберите отсутствующий каталог под существующим родителем. Шаблон принимает
абсолютный HTTPS URL либо HTTP на loopback. Учётные данные, фрагменты URL и
неразрешённые подстановки в адресе не допускаются. Не включайте пароль в URL.

## Назначение файлов

```text
docs-service/
  plugin.json
  mcp.json
  README.md
  .gitignore
```

Корневой манифест задаёт идентичность пакета. В `mcp.json` сервер находится под
`mcpServers`; шаблон использует `type: streamable-http` и переданный URL.
Сервер и Skill не создаются. Для инструкций рядом с инструментами выберите
[гибридный пакет](./hybrid).

В README опишите назначение сервиса, необходимые учётные записи и источник
инструкций по аутентификации. Секреты храните вне пакета. Корректный URL в файле
не подтверждает доступность сервиса.

## Проверьте конфигурацию и целевые клиенты

```bash
agentplugins author validate ./docs-service
agentplugins author inspect ./docs-service --target codex,claude
agentplugins author test ./docs-service
agentplugins author compat ./docs-service --target codex,claude
agentplugins author doctor ./docs-service
```

`inspect` показывает компоненты и недостающие требования; `compat` проверяет
статическую поддержку адаптеров. Установленные клиенты не нужны. Doctor не
обращается к конечной точке. Явная проверка MCP с сетью описана в
[руководстве по проверкам](./checks).

## Обозначьте оставшиеся действия

Укажите транспорт и предназначенные клиенты в отчёте. Установщик отдельно
оценивает политику установки и выводит действия по активации. Пользователю могут
потребоваться вход, подтверждение доступа или новый сеанс. Обнаружение и вызов
MCP-инструментов требуют отдельных результатов.

Сначала исправляйте ошибки конфигурации. Если позднее сервис недоступен,
проверяйте сам сервис и соединение клиента: повторный статический тест не
является проверкой связи.

Далее: [смысл результатов](./checks) и [передача установщику](./handoff).
