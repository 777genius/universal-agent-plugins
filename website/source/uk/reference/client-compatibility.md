# Докази сумісності клієнтів UAP {#uap-client-compatibility-evidence}

## Поточний випуск та область застосування {#current-release-and-scope}

[CLI 0.1.94](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.94), нативний випуск від 28 жовтня 2026 року, додає
автоматичний вибір проєкту для `install` без аргументу джерела, якщо саме в
поточній папці є звичайний файл `uap.toml`. Явна область має пріоритет;
батьківські папки не перевіряються. Наявні файли фіксації суворо перевіряються
навіть без `--locked`. Явне встановлення для проєктів з'явилося в 0.1.93.
Ці докази випуску інсталятора не кваліфікують виконання в кожному нативному
агенті чи виконуваний файл стандартних інструментів розробки. Поточний
npm/нативний інсталятор не містить `agentplugins author`; інструменти з вихідного
коду описано в [посібнику зі створення](../build/).

Розглядайте сумісність як кілька окремих питань:

| Перевірка | Значення |
| --- | --- |
| Відповідність пакета | Стандартні файли пакета відповідають контракту завантажувача та схем. |
| Доставка компонентів | Адаптер підготував або встановив належні йому компоненти. |
| Нативне виявлення | Конкретний клієнт виявив потрібний компонент. |
| Виконання MCP | Записаний процес або з'єднання ініціалізувався й виконав перевірені виклики. |
| Автентифікація та використання моделі | Підтверджуються лише коли докази явно їх перевіряють. |

Встановлення для проєкту часто залишається у стані **Prepared**, поки не виконано
кроки довіри, перезавантаження, явного налаштування або сеансу. Встановлення для
проєкту ChatGPT явно не підтримується. Область проєкту VS Code готує файли для
однієї локальної папки; спостереження метаданих за закріпленою версією не є
доказом запуску MCP чи виконання моделі. Див. [підтримку проєктів за клієнтами](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_CLIENT_SUPPORT.md)
та [покажчик доказів проєктів](https://github.com/777genius/universal-agent-plugins/blob/main/docs/evidence/PROJECT_INSTALLATION.md).

Наведені нижче записи зберігають точні історичні випуски, версії клієнтів,
ідентифікаційні дані платформ та спостережені обмеження. Вони не поширюються
автоматично на 0.1.94, новішу версію клієнта, іншу область або неперевірений
пакет. UAP — незалежний інструмент спільноти; це обмежені спостереження
супроводжувачів, а не сертифікація постачальників чи твердження про загальну
готовність до промислового використання.

## Історична чернетка інсталятора 0.1.55 {#historical-draft-installer-0155}

**На записаному контрольному етапі у вересні 2026 року 0.1.55 була неопублікованою
чернеткою.** Ці результати кваліфікують ті знімки чернетки; вони не описують
поточний статус випуску й не є інструкцією оновлення. Наведені нижче докази
випущеної 0.1.53 залишаються чинними та окремими.

У двох незалежно кваліфікованих областях **12 напрямів перевірки нативних клієнтів
пройшли всі 24 обов'язкові тести верхнього рівня без пропусків**. Кожен
використовував початковий npm tarball виробника, автономне встановлення npm
з вимкненими скриптами, холодний початковий запуск із зафіксованого нативного
бінарного файлу та теплий запуск без вихідного коду перевірки. Справжні клієнти
закріплених версій працювали у свіжих тимчасових профілях.

| Перевірений клієнт | Linux arm64 | Linux amd64 | macOS arm64 | Windows amd64 |
| --- | --- | --- | --- | --- |
| Codex 0.153.4 | Життєвий цикл, stdio/HTTP та контекст Skill пройшли | Той самий обсяг пройшов | Той самий обсяг пройшов | Той самий обсяг пройшов |
| Claude Code 2.1.263 | Життєвий цикл, stdio/HTTP та встановлені Skills пройшли | Той самий обсяг пройшов | Той самий обсяг пройшов | Життєвий цикл HTTP/встановлених Skills пройшов; керований stdio не підтримується |
| OpenCode 1.18.29 | Набори життєвого циклу, розширених stdio/Skill та спостереження колізій пройшли | Той самий обсяг пройшов | Той самий обсяг пройшов | Той самий обсяг пройшов |

Життєвий цикл охоплює встановлення, оновлення, оновлення тієї самої версії,
відновлення та видалення. Claude у Windows повідомляє
`managed_stdio_platform_unsupported`; його виконання stdio та поведінку
cwd/argv/env/даних не підтверджено. Спостережена колізія OpenCode залишається
невирішеною з попередженням `opencode_tool_namespace_not_evaluated`. Життєвий
цикл JSONC не доводить виконання stdio/основного тексту Skill у JSONC.
Точка підміни отримання Git у тестах Codex не є новим твердженням про нативне
виконання з публічного Git.

[Історичний запуск дев'яти напрямів](https://github.com/777genius/universal-agent-plugins/actions/runs/34309083566) пройшов дев'ять напрямів і
18 обов'язкових тестів із тестовою обв'язкою `0cfa2b7`; остаточна повторна
перевірка чернетки відбулася **2026-09-09T04:10:39.529018+00:00**.
[Запуск Linux amd64](https://github.com/777genius/universal-agent-plugins/actions/runs/34307075390) пройшов три напрями та шість обов'язкових тестів
з обв'язкою `fde7298`; остаточна повторна перевірка чернетки відбулася
**2026-09-09T03:36:42.614887+00:00**. Обидва прив'язані до того самого
зафіксованого [запуску виробника](https://github.com/777genius/universal-agent-plugins/actions/runs/34305637370). [Стислі метадані доказів](https://github.com/777genius/universal-agent-plugins/blob/main/docs/evidence/client-compatibility-draft-0.1.55.json)
записують точні ідентифікаційні дані виробника, пакета, обв'язки, кваліфікації
та архівів.

Обидві збережені області пройшли автономну перевірку. Свіжа копія засобу перевірки
на `0cfa2b7` також повторно перевірила збережену область Linux amd64 `fde7298`;
це не був новий нативний запуск чи жива повторна перевірка чернетки, і час
кваліфікації не змінився. Узгодженість хешів архіву не є свіжою перевіркою
атестацій або доказом поточного стану чернетки. Необроблені журнали та архіви
залишаються приватними до перевірки можливості розкриття; публічні лише метадані.

Це спостереження супроводжувачів зі справжніми клієнтами, сценарними
провайдерами моделей на loopback та мережевим доступом. Тимчасові профілі та
явні середовища дочірніх процесів не забезпечують ізоляції ОС/процесів.
Звідси не випливають твердження про реальні моделі, OAuth/вхід, настільні
застосунки, живі сервіси, сертифікацію постачальників, офіційний статус або
незалежне впровадження. Коректність пакета, встановлення, активація, виконання
та OAuth залишаються окремими рівнями доказів. Цей доказ інсталятора не
кваліфікує випуск виконуваного файлу стандартних інструментів розробки (D5).

### Історична матриця нативних CLI Linux arm64 {#historical-linux-arm64-native-cli-matrix}

Кожен запуск використовував новий тестовий проєкт та окремі корені HOME/клієнта/XDG
у контейнері. Виконання використовувало loopback MCP-сервери та сценарних
провайдерів без облікових даних користувача чи реальної моделі. Дайджест образу
контейнера:
`sha256:df6ab45e95c4425fcdccfc9a143bec29e2bf08293b63482c7843f398e06baabb`.
У стислому записі не зазначено версію дистрибутива.

| Рівень доказів | Codex 0.153.4 | Claude Code 2.1.263 | OpenCode 1.18.29 |
| --- | --- | --- | --- |
| Коректність стандартного пакета | Окрема перевірка завантажувача/відповідності | Окрема перевірка завантажувача/відповідності | Окрема перевірка завантажувача/відповідності |
| Шлях встановлення | Локальний пакет, керований marketplace/нативний плагін | Локальний пакет, персональний `@skills-dir` | Глобальні JSON та JSONC, окремі сценарії |
| Встановлення, оновлення версії, оновлення тієї самої версії, відновлення, видалення | Пройдено | Пройдено | Пройдено |

Встановлення, активація та виконання — окремі спостереження. Жодне не замінює
перевірку за опублікованим контрактом Agent Plugins. Історичний цикл адаптера
Linux не повторював закріплений корпус тестів відповідності та не робить нового
твердження про відповідність. Запити сценарних провайдерів доводять спостережену
поведінку клієнта та виклики інструментів; вони не доводять міркування реальної
моделі чи успішний OAuth.

Розширений запуск OpenCode використовує образ
`sha256:cf4b5019fbb6d887a96ff066402594b367b7df75c90a86813d9ab9ef5fa491cb`
з автономним ripgrep 14.1.1. Він повторно використовує точні ідентифікаційні
дані інсталятора вище; SHA-256 джерела тесту —
`55314bbed0587390965914a2d685a3b16d0ea926950625cc4dd91ab95ea2b0d4`.
Незалежна перевірка звірила всі 21 згаданий хеш стенограм та 81 хеш маніфестів
вихідних файлів. Одноразовий маркер BODY із Skill потрапляє у вихідний контекст
інструмента та відсутній у початкових метаданих/визначеннях інструментів;
це не підтверджує розуміння моделлю. Запуск не доводить новий код інсталятора
або іншу ОС.

### Історичні обмеження та вужчі докази {#historical-limitations-and-narrower-proofs}

- **Колізія назв інструментів OpenCode:** логічні ключі `api/server` та `api server` працюють окремо, але разом надають одну викличну назву `api_server_inspect_runtime`, хоча обидва каталоги MCP видимі. Збереження ключів конфігурації не означає унікальність викличних назв. Контрольна точка джерела `c154185` додає попередження `opencode_tool_namespace_not_evaluated` до виводу доставки CLI. Воно попереджає про непідтримувані комбінації з колізіями під час виконання; не перейменовує інструменти, не доводить унікальності та не робить стандартний пакет некоректним.
- Сценарії OpenCode HTTP підтверджують збереження сторонньої конфігурації JSON/JSONC і відмову при колізіях. Окремий глобальний JSON-запуск `opencode-extended-11` доводить cwd, argv/env stdio, одноразове розкриття токенів та сталість даних. Після видалення відсутні й інструменти, і метадані Skill, без активності проби та зі спостереженим реальним запитом до основного провайдера. Покриття stdio/тексту у JSONC не припускається.
- Codex виключив SSE, некоректні Skills і відсутні середовища виконання; ізолював помилку запуску виконуваного файлу; зберіг працездатність справних викликів; відхилив повністю непідтримувані вхідні дані без змін. Claude не перевіряв усю цю матрицю помилок. OpenCode довів виключення SSE зі справними сусідніми компонентами, а не повну матрицю Codex.
- Codex спостерігав пріоритет HTTP-протоколу/заголовків і перенаправлення, за яким клієнт не переходив на інший origin. Claude й OpenCode довели HTTP-виклики без незалежної перевірки перенаправлень/пріоритету заголовків.
- Codex і Claude довели статичний захист стороннього вмісту та змін у межах своїх сценаріїв. Окремі регресійні тести охоплюють гонки відкату публікації; це не гарантія проти довільних конкурентних записів у файлову систему.
- `git-01` довів фактичне отримання з публічного незмінного Git, встановлення, активацію, нативне виявлення Skill у Codex та видалення. Його сценарій лише зі Skill був [AP-6.2-MISSING-LOCATION-OK на закріпленому коміті корпусу](https://github.com/Booyaka101/agent-plugins-conformance-kit/tree/4d163c6281a9b4929f482f387efe340b4dc175a1/fixtures/core/AP-6.2-MISSING-LOCATION-OK/plugin). Мережевий доступ завершився до нативного виявлення. Виконання Git MCP та незмінне перемикання/оновлення не оцінювалися. Нативні запуски Git для Claude/OpenCode не оцінювалися. Встановлення з локального та незмінного Git не потребують Directory.

### Історична контрольна точка джерела macOS arm64 і Windows amd64 {#historical-macos-arm64-and-windows-amd64-source-checkpoint}

[Запуск GitHub Actions 34158664586](https://github.com/777genius/universal-agent-plugins/actions/runs/34158664586) пройшов усі шість обов'язкових
напрямів нативних клієнтів без пропусків на коміті джерела
[`ef20b9314b69d4094f4922946b8ad39024371202`](https://github.com/777genius/universal-agent-plugins/commit/ef20b9314b69d4094f4922946b8ad39024371202), дерево
`4ba999db51304b056ec559c5429ed9aab9aace60`. Усі **348 індексованих хешів
артефактів** було перевірено. Це нативні докази саме для тієї контрольної
збірки з вихідного коду, а не історичного інсталятора Linux, опублікованого
бінарного файлу чи твердження про проходження всіх перевірок якості/випуску
репозиторію.

| Перевірений клієнт | macOS arm64 | Windows amd64 |
| --- | --- | --- |
| Codex 0.153.4 | Нативний життєвий цикл, виконання stdio/HTTP та сценарний контекст Skill пройшли | Нативний життєвий цикл, виконання stdio/HTTP та сценарний контекст Skill пройшли, зокрема видалення, повторне видалення й збереження стороннього вмісту |
| Claude Code 2.1.263 | Нативне виявлення та сценарний життєвий цикл виконання stdio/HTTP пройшли | Життєвий цикл HTTP і встановленого Skill пройшов; керований stdio явно не підтримується |
| OpenCode 1.18.29 | Усі три набори пройшли: життєвий цикл JSON/JSONC, розширені stdio/основний текст Skill, колізії інструментів HTTP | Усі три набори пройшли: життєвий цикл JSON/JSONC, розширені stdio/основний текст Skill, колізії інструментів HTTP |

Для Codex і OpenCode успішний життєвий цикл містить встановлення, оновлення
версії, оновлення тієї самої версії, відновлення та видалення. Розширений
глобальний набір JSON OpenCode окремо доводить сталість cwd/argv/env/даних stdio
та вихідний текст Skill; це не припускає покриття stdio/тексту у JSONC та не
усуває спостережену колізію назв інструментів. Codex також перевіряє незмінне
отримання у своєму нативному наборі. Коректність стандартного пакета залишається
окремою від цих спостережень клієнтів.

**Claude у Windows має вужчий контракт виконання.** Нативні етапи HTTP та
встановленого Skill пройшли A/B/C, відновлення й видалення зі збереженням даних
інсталятора. Керований stdio повідомляє точну діагностику готовності
`managed_stdio_platform_unsupported`. Виконання stdio спостерігається як
непідтримуване; поведінка cwd/argv/env/даних stdio залишається неоціненою.
Це явне обмеження платформи не робить переносний пакет некоректним і не блокує
перевірені справні компоненти HTTP/Skill.

Це були тимчасові машини на хостингу GitHub зі свіжими профілями й тестовими
проєктами. Версії ОС не записано у стислих записах виконавців.
**Мережу не було заблоковано**; кінцеві точки моделей були сценарними
loopback-сервісами. Точні дайджести клієнтів/збірок і доказів виконавців є
у стислому записі. Ці запуски не дають підстав для тверджень про реальні
моделі, вхід, OAuth чи настільні застосунки.

Нативні сценарії, обгортка виконавця та нативний workflow побайтово тотожні
незалежно перевіреній контрольній точці `a6462a7`. Їхня семантична перевірка
використовується повторно; нові артефакти запуску незалежно перевірено за
хешами. Це не замінює перевірку інших змін продукту між комітами.

Попередні контрольні точки, зокрема невдалі напрями Windows, залишаються
в ідентифікаційних даних доказів як історія. Цей запуск замінює їхній підсумок
платформ; помилки не були перейменовані на успіхи.

## Докази області проєкту {#project-scope-evidence}

Явне встановлення для проєкту випущено в CLI 0.1.93. Наведені вище історичні
випуски й нативні спостереження зберігають початкову область. Встановлення для
проєкту має окремий контракт кожного клієнта: належність установлених файлів,
нативне виявлення та робота MCP/моделі звітуються окремо. Область проєкту
ChatGPT явно відхиляється; інші цілі мають власні обмеження компонентів,
підготовки або тестової обв'язки.

Підготовка проєкту VS Code використовує `.github/skills` і `.vscode/mcp.json`.
[Спостереження закріпленої VS Code 1.143.1](https://github.com/777genius/universal-agent-plugins/actions/runs/40188310034) перевірило метадані
в окремих папках A/B, новий запуск A та видалення без наданої довіри до робочої
області. Це докази метаданих; адаптер повідомляє Prepared і перевірку
встановлених файлів, не стверджуючи запуск MCP, виклики інструментів чи
виконання моделі.
