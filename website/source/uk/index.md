## Установіть свій перший плагін {#install-your-first-plugin}

З Node.js 22 або новішою версією:

```bash
npx universal-agent-plugins add context7
```

CLI запитає, які сумісні агенти використовувати. Перегляньте план і виконайте
зазначені в результаті кроки активації або входу. Потрібен нативний виконуваний
файл? У [посібнику з нативного встановлення](https://github.com/777genius/universal-agent-plugins/blob/main/docs/NATIVE_INSTALL.md)
є інструкції для macOS, Linux і Windows; самому нативному менеджеру Node.js не потрібен.

## Що доступно зараз {#what-is-available}

[CLI 0.1.95](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.95)
— поточний нативний випуск інсталятора від 29 жовтня 2026 року. Він додає
локальний API керування та нативні розширення Pi в області користувача.
Див. [локальне керування](./use/manage#local-management-api) та
[сумісність із Pi](./reference/client-compatibility#pi-native-extensions).

Інсталятор підтримує явний вибір області проєкту та відновлення за файлом фіксації
залежностей. Більшість команд за замовчуванням працює із середовищем користувача.
Команда `install` без аргументу джерела обирає поточний проєкт, якщо саме в цій
папці є звичайний файл `uap.toml`; явний вибір області має пріоритет. Для команд
обслуговування обирайте область проєкту явно. Перевірте `agentplugins version`:
автоматичний вибір потребує 0.1.94. Канали менеджерів пакетів можуть відставати;
перевірений поточний випуск доступний через нативний інсталятор. Явні прапорці
проєкту підтримуються з 0.1.93. Див. [встановлення](./use/install) та
[обслуговування](./use/manage).

Поточний інсталятор не містить `agentplugins author`.
[Посібник зі створення](./build/) пояснює ручне написання пакетів і команди
розробки, реалізовані в поточному вихідному коді. Історичні докази випусків
інструментів розробки зберігають свої початкові версії та не описують поточне
завантаження інсталятора.

## Як тлумачити результат {#understand-the-result}

Перевірка пакета, встановлення, виявлення клієнтом, виконання MCP-інструментів і
автентифікація в сервісі — окремі перевірки. Після успішного запису файлів клієнт
може ще потребувати дозволу довіри, перезавантаження або нового сеансу. Нативні
тести охоплюють конкретні версії клієнтів і платформи; вони не підтверджують
працездатність усіх плагінів чи агентів.
