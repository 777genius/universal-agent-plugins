# Використання плагінів {#use-plugins}

Universal Agent Plugins установлює стандартні пакети для обраних ШІ-агентів.
Пакет може містити Skills, конфігурацію MCP-серверів або обидва компоненти.
Можна встановити його для свого облікового запису або відокремити залежності
окремого проєкту.

## Отримайте CLI {#get-the-cli}

З Node.js 22 або новішою версією можна запускати npm-обгортку безпосередньо:

```bash
npx universal-agent-plugins search docs
```

Для регулярного використання встановіть її глобально:

```bash
npm install -g universal-agent-plugins
agentplugins version
```

Ще один варіант — Homebrew:

```bash
brew install 777genius/agentplugins/agentplugins
```

[Посібник із нативного встановлення](https://github.com/777genius/universal-agent-plugins/blob/main/docs/NATIVE_INSTALL.md)
містить інструкції для macOS, Linux і Windows. Нативному менеджеру Node.js не
потрібен, хоча окремі плагіни можуть потребувати власного середовища виконання.
У прикладах цього посібника використано `agentplugins`; ті самі команди
інсталятора можна запускати через `npx universal-agent-plugins`.

## Пройдіть шлях встановлення {#follow-the-installation-journey}

1. [Знайдіть і перевірте пакет](./install). З'ясуйте його джерело та передумови.
2. Перегляньте план для потрібних клієнтів і області за допомогою `--dry-run`.
3. Застосуйте перевірений план і виконайте інструкції з активації.
4. [Обслуговуйте встановлені пакети](./manage): переглядайте список, оновлюйте, відновлюйте та видаляйте їх.
5. За потреби відновіть спільний набір залежностей з `uap.toml` і `uap.lock`.

[CLI 0.1.95](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.95)
— поточний нативний інсталятор. Він додає локальний API керування та нативні
розширення Pi в області користувача. Див.
[локальне керування](./manage#local-management-api) та
[сумісність із Pi](../reference/client-compatibility#pi-native-extensions).
Канали менеджерів пакетів можуть відставати; перевіряйте `agentplugins version`.
Перевірений поточний випуск доступний через нативний інсталятор.

Явна область проєкту підтримується з 0.1.93. Більшість команд за замовчуванням
працює в області користувача. Починаючи з 0.1.94, `install` без аргументу джерела
чи явної області обирає проєкт лише тоді, коли звичайний файл `uap.toml` є саме
в поточній папці; батьківські папки не перевіряються. Для обслуговування проєкту
вказуйте `--scope project`. Підтримка проєктів та активація залежать від цільового
клієнта.

## Оцінюйте кожен рівень результату {#read-the-result-at-the-right-level}

Після встановлення клієнт може ще потребувати перезавантаження, підтвердження
довіри, ручної активації або OAuth. Статус Prepared означає, що в клієнті
залишилися додаткові кроки. Читайте результат для кожного клієнта, а не
сприймайте завершення всієї операції як доказ успішного виконання. Див.
[сумісність клієнтів](../reference/client-compatibility), щоб дізнатися, які
докази стоять за спостереженнями для конкретних версій нативних клієнтів.

## Якщо ви створюєте пакет {#if-you-are-writing-a-package}

Почніть зі [створення плагінів](../build/). Результат для передачі — каталог із
кореневим `plugin.json` та компонентами. Користувачеві інсталятора не потрібно
запускати інструменти розробки зі збірки з вихідного коду.

| Команда | Призначення |
| --- | --- |
| `agentplugins validate ./my-plugin` | Прочитати та перевірити локальний пакет для встановлення. |
| `agentplugins doctor` | Діагностувати стан, яким керує інсталятор. |
| `agentplugins author validate ./my-plugin` | Перевірити відповідність і готовність пакета у збірці з вихідного коду з увімкненими інструментами розробки. |
| `agentplugins author doctor ./my-plugin` | Дослідити докази щодо проєкту та інструментарію в цій збірці. |

Поточний випуск npm і нативного інсталятора не містить `agentplugins author`.
