# Пошук і встановлення плагіна {#find-and-install-a-plugin}

Обирайте пакет, джерело та призначення якого вам зрозумілі. Наведені нижче команди
використовують випущений інсталятор; якщо `agentplugins` ще немає, див.
[встановлення CLI](./). Перед застосуванням змін переглядайте план за допомогою
`--dry-run`.

## Знайдіть пакет {#discover-the-package}

```bash
agentplugins search docs
agentplugins info context7
```

Коротка назва, наприклад `context7`, надходить із підписаного Universal Agent
Plugins Registry. Пошук і відомості про пакет допомагають обрати варіант; вони не
запускають його та не доводять доступність сервісу. Перед встановленням
перегляньте доступні інструменти, Skills, вимоги до середовища виконання та
доступу до облікових записів.

## Перегляньте план для явно обраних клієнтів {#preview-one-explicit-selection}

```bash
agentplugins add context7 --target codex,cursor --dry-run
```

Перевірте джерело, обрані клієнти, місця встановлення, результати перевірок
безпеки та подальші кроки активації. Команда виводить план, не застосовуючи
встановлення. Вона не тестує MCP-сервер.

## Установіть пакет після перевірки плану {#install-after-reviewing-the-plan}

```bash
agentplugins add context7 --target codex,cursor
```

Для інтерактивного вибору не вказуйте `--target`. CLI може автоматично обрати
єдиного виявленого агента або запропонувати список, якщо їх кілька. Для
відтворюваного вибору та автоматизації вказуйте клієнти явно.

Інсталятор попередньо перевіряє обрані клієнти та захищає файли, якими не володіє.
Якщо операція повідомляє про невдалий відкат або незавершене відновлення,
збережіть звіт і виконайте його вказівки з відновлення перед повторною спробою.

## Завершіть активацію {#finish-activation}

Виконайте зазначені в результаті кроки для свого клієнта: може знадобитися
перезавантаження, новий сеанс, довіра до робочої області, вхід або явна активація.
Підготовлені файли та успішна нативна реєстрація не доводять проходження OAuth
чи успішних викликів інструментів. Якщо встановлення відсутнє або має розбіжності,
скористайтеся [діагностикою керованого стану](./manage); якщо пакет є, але
недоступний, перевірте автентифікацію в клієнті.

## Використайте локальний пакет {#use-a-local-package}

Оберіть каталог із кореневим `plugin.json`:

```bash
agentplugins validate ./my-plugin
agentplugins add ./my-plugin --target codex --dry-run
```

Перевірка інсталятора та планування й далі застосовують політику безпеки.
Навіть для локального пакета вони можуть завантажувати метадані безпеки або
сканер закріпленої версії; `--dry-run` запобігає змінам керованого встановлення,
але не гарантує роботу без мережі.

Після перевірки плану приберіть `--dry-run`, щоб установити пакет. Локальний
каталог залишається локальним встановленням; це не переносна залежність, яку
інший комп'ютер зможе завантажити. Попросіть автора надати
[докази для передачі пакета](../build/handoff).

## Оберіть точне джерело GitHub {#select-an-exact-github-source}

Усталений синтаксис незмінного джерела GitHub потребує повного SHA коміту із
40 символів. Замініть цей приклад реальним репозиторієм, перевіреною ревізією
та шляхом до пакета:

```text
agentplugins add owner/repository@0123456789abcdef0123456789abcdef01234567//path/to/plugin --target codex --dry-run
```

Форма `owner/repository@...` не приймає гілки, теги та скорочені SHA. Без шляху
інсталятор обирає коректний пакет у корені або єдиного коректного вкладеного
кандидата. Якщо кандидатів кілька, потрібен явний шлях; якщо можливих пакетів
понад 16, його потрібно вказати ще до завантаження кандидатів. Відновлення
повторно використовує записане джерело. Перехід незмінного встановлення на інше
джерело є окремою операцією вибору джерела.

CLI 0.1.93 також приймає прямі HTTPS Git і SSH-адреси, підтримувані вебадреси
провайдерів та повні HTTPS- або локальні архіви. Наприклад, замініть ці
заповнювачі перевіреними джерелами пакетів:

```text
agentplugins add 'https://git.example.com/team/tools.git#refs/heads/main//plugins/demo' --target codex --dry-run
agentplugins add 'ssh://git@git.example.com/team/tools.git#main//plugins/demo' --target codex --dry-run
agentplugins add 'https://downloads.example.com/plugin.tar.gz' --target codex --dry-run
```

Git використовує наявні нативні облікові дані та довіру до SSH-хоста.
HTTPS-архіви не використовують облікових даних і мають містити повний стандартний
пакет. Файл фіксації закріплює точні ревізії Git або початкові байти архіву разом
із дайджестами пакета. Рухоме джерело може перейти на нову версію через явне
оновлення; відновлення за файлом фіксації зберігає закріплену версію. Такі
джерела повних пакетів відрізняються від отримання окремих Skills.
Див. [прямі джерела повних пакетів](https://github.com/777genius/universal-agent-plugins/blob/main/docs/DIRECT_PACKAGE_SOURCES.md):
синтаксис провайдерів, вибір пакетів, контрольні суми та обмеження розпакування.

## Установіть Agent Skills {#install-agent-skills}

Група команд `skills` установлює окремі Skills із публічного репозиторію GitHub,
URL папки або `SKILL.md`, а також від HTTPS-видавця з повним індексом Skills
у `.well-known`:

```bash
agentplugins skills add owner/repository --ui
```

Замініть `owner/repository` реальним джерелом. `--ui` відкриває вбудований
браузерний інтерфейс вибору та потребує інтерактивного термінала. Для вибору
в терміналі використовуйте `--no-ui`. Для явного вибору:

```bash
agentplugins skills add owner/repository --skill review --skill pdf \
  --target codex,claude --no-ui --yes
```

- Повторюйте `--skill` для точних назв. Якщо назва неоднозначна, задайте точну папку Skill відносно репозиторію через `--path`.
- `--ref` обирає точне посилання Git, якщо межі частин URL неоднозначні.
- `--dry-run` показує план обраного встановлення.
- Для JSON і неінтерактивного використання потрібні явний вибір Skills, клієнти та `--yes`, окрім попереднього перегляду через `--dry-run`.
- `--ui` не можна поєднувати з `--skill`, `--target` або `--dry-run`.
- Для HTTPS-видавців потрібна точна назва `--skill` та індекс із переліком усіх файлів цього Skill.

Результати автоматичних перевірок безпеки можуть заблокувати встановлення.
`--security-details` показує подробиці у виводі для людини; перегляньте їх, перш
ніж вирішувати, чи доречний явний `--accept-security-risk`. Установлені Skills
відображаються в `agentplugins list` та обслуговуються звичайними командами.

## Установіть для окремого проєкту {#install-for-one-project}

Явна область проєкту доступна в
[CLI 0.1.93 і новіших версіях](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.93).
Оберіть наявний каталог і вказуйте область у кожній команді:

```bash
agentplugins add context7 --target cursor --scope project \
  --project-root /path/to/project --dry-run
agentplugins skills add owner/repository --ui --scope project \
  --project-root /path/to/project
```

Перша команда лише показує план; приберіть `--dry-run`, коли будете готові його
застосувати. Друга відкриває інтерфейс вибору в заданій області та може застосувати
вибір користувача. Без `--project-root` явна область проєкту використовує каталог
виклику. Пошуку в батьківських папках немає. В інших випадках команди додавання
та обслуговування за замовчуванням працюють в області користувача. У CLI 0.1.94
команда `install` без аргументу джерела обирає область проєкту, якщо саме в поточній
папці є звичайний файл `uap.toml`; явна область має пріоритет. Див.
[правила відновлення](./manage), зокрема сувору перевірку файлу фіксації.

Цільовий клієнт має підтримувати запитані компоненти проєкту. Встановлення для
проєкту ChatGPT явно не підтримується. VS Code готує `.github/skills` та належні
інсталятору члени `servers` у `.vscode/mcp.json` для однієї локальної папки.
Результат залишається Prepared: перевірте довіру до робочої області й серверів
та налаштування клієнта. Це спостереження метаданих не доводить запуск MCP,
виклики інструментів або використання моделі.

Див. [посібник зі встановлення для проєкту](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_INSTALLATION.md)
та [межі підтримки клієнтів у проєктах](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_CLIENT_SUPPORT.md)
щодо шляхів і обмежень активації. Продовжуйте з [обслуговування та відновлення](./manage).
