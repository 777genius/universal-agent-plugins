# Корінь і структура пакета {#understand-the-package-root}

**Розробка у збірці з вихідного коду:** команди на цій сторінці потребують
[збірки з увімкненими інструментами розробки](./#build-from-source).
Поточний випуск інсталятора не містить `agentplugins author`.

Обраний каталог є коренем пакета. Інструменти розробки читають кореневий
`plugin.json` і стандартні компоненти. Вони не шукають проєкт у батьківських
каталогах та не переходять до прихованого маніфесту нативного клієнта.

## Мінімальна та комбінована структури {#minimal-and-combined-layouts}

Пакет лише зі Skill:

```text
review-helper/
  plugin.json
  skills/
    review-docs/
      SKILL.md
```

Віддалений гібридний пакет:

```text
research-helper/
  plugin.json
  mcp.json
  skills/
    research-guide/
      SKILL.md
```

Пакет stdio також містить вихідний код середовища виконання та маніфести
залежностей. Ці файли потрібні для подальшого виконання, але їх наявність не
змушує інструменти читання запускати будь-що.

## Визначте чітке призначення кожного файлу {#give-each-file-a-clear-responsibility}

| Файл або каталог | Призначення |
| --- | --- |
| `plugin.json` | Стандартні ідентифікаційні дані та метадані пакета. |
| `mcp.json` | Конфігурація MCP-серверів, якщо пакет надає інструменти. |
| `skills/<name>/SKILL.md` | Ідентифікаційні дані, опис та інструкції одного Skill у підкаталозі `skills/` першого рівня. |
| `README.md` | Призначення, передумови, перевірки та відомі обмеження. |
| `package.json`, `package-lock.json`, `src/server.mjs` | Файли заготовки Node stdio для окремої роботи з виконанням. |
| `LICENSE` | Явно обрана ліцензія, якщо її задано під час init. |

Заготовка починає версію маніфесту з `0.1.0`. Це метадані вашого нового пакета,
а не версія випуску інструмента розробки. Розрізняйте їх, повідомляючи версії
користувачам.

## Ідентифікаційні дані та необов'язкові метадані {#identity-and-optional-metadata}

У відтворюваних інструкціях init явно вказуйте `--name` і `--description`.
Публічний інтерфейс може вивести назву з простого імені каталогу призначення та
надає детермінований типовий опис, але для шляхів на зразок `./review-helper`
слід указувати назву явно. У цих посібниках задано обидва параметри, щоб
уникнути випадкової ідентифікації.

Для шаблонів зі Skill параметр `--skill-name` за відсутності значення дорівнює
назві пакета. Укажіть його явно, якщо Skill потребує іншої назви. Назви Skills
ніколи не нормалізуються мовчки.

Необов'язковий `--author-name` задає автора явно. Автор не визначається з Git
чи середовища. Генерування ліцензії підтримує явний вибір MIT або ISC та потребує
і `--copyright-holder`, і чотиризначного `--copyright-year`. Типової ліцензії немає.

## Послідовно обирайте той самий корінь {#select-the-root-consistently}

```bash
agentplugins author validate ./research-helper
agentplugins author inspect ./research-helper
agentplugins author test ./research-helper
```

Усі три команди обирають той самий корінь пакета. Передача
`./research-helper/skills` обере неправильний каталог. Необов'язковий шлях
у командах читання за замовчуванням означає лише поточний каталог, а не
автоматично знайденого батьківського каталогу.

Відповідність стандарту та безпека файлової системи — окремі питання. Назва,
що відповідає схемі, усе ще може бути непридатною як шлях на хості, а самого
читабельного маніфесту може бути недостатньо для підтвердження компонентів.
Використовуйте повний звіт.

Продовжуйте зі [статичних перевірок](./checks), а потім [передачі](./handoff).
