# Додавання Skills {#add-extra-skills}

**Розробка у збірці з вихідного коду:** команди на цій сторінці потребують
[збірки з увімкненими інструментами розробки](./#build-from-source).
Поточний випуск інсталятора не містить `agentplugins author`.

Операція `skills init` додає один Skill до наявного стандартного пакета.
Вона працює з пакетами Skill, MCP і гібридними пакетами. Обирайте корінь пакета,
який містить `plugin.json`, а не каталог `skills/` чи окремий файл `SKILL.md`.

## Укажіть назву нового Skill та пакет {#name-the-new-skill-and-package}

Припустімо, `./review-helper` — пакет із [посібника з окремого Skill](./skill),
а `skills/release-notes/` ще не існує.

У збірці з увімкненими інструментами розробки:

```bash
agentplugins author skills init release-notes ./review-helper \
  --description 'Застосовуйте для написання приміток до випуску з перевірених змін'
```

Позиційна назва Skill обов'язкова, як і явний опис завдовжки 1–1024 символи.
Назви не нормалізуються. Використовуйте точну переносну назву малими літерами
з дефісами та обирайте нове місце призначення, не очікуючи перезапису.

## Перегляньте доданий компонент {#review-the-additional-component}

```text
review-helper/
  plugin.json
  skills/
    review-docs/
      SKILL.md
    release-notes/
      SKILL.md
```

Відредагуйте `skills/release-notes/SKILL.md`: поясніть умови застосування, метод
і очікуваний результат. Підтримуйте точність назви й опису. Наприклад, доручіть
відокремлювати видимі користувачам зміни від технічного обслуговування та
посилатися на перевірене джерело для кожного твердження у примітках до випуску.

Скрипти, довідкові матеріали та ресурси можуть доповнювати інструкції, але сама
їх наявність не доводить виконання та не дає дозволу на запуск. Поле
`allowed-tools` не є самостійним доказом дозволу. Переглядайте допоміжні матеріали
так само уважно, як і текст інструкцій.

## Перевірте пакет і його Skills {#validate-the-package-and-immediate-skills}

```bash
agentplugins author skills validate ./review-helper
```

Команда звітує про готовність усього пакета та надає окремі результати для
Skills у підкаталогах `skills/` першого рівня.
Тому помилка в іншій частині пакета може вплинути на загальний результат,
навіть якщо в самого нового Skill проблем немає.

Якщо шлях до пакета не вказано, використовується лише поточний каталог без
пошуку в батьківських. Явні корені роблять скрипти й діагностику зрозумілішими.
Запуск усередині `skills/release-notes/` не замінює вибір кореня пакета.

## Усуньте помилку, не перезаписуючи роботу {#handle-a-failure-without-overwriting-work}

Якщо створення завершилося помилкою, прочитайте `committed` та супровідні
вказівки. Skill може бути вже записаний, хоча подальші перевірки пакета не
пройшли або залишилися незавершеними. Перед повторною спробою огляньте фактичні
файли та звіт; повторний init у наявному місці призначення не перезапише його.

Виправте зазначені вхідні дані чи проблему пакета та повторіть перевірку.
Якщо назва неправильна, явно перегляньте потрібну зміну вихідних файлів замість
додавання прапорця примусового виконання. Установлення й обслуговування зовнішніх
Skills належать до окремого шляху інсталятора; `author skills` редагує та перевіряє
компоненти у вашому вихідному пакеті.

Продовжуйте зі [статичних перевірок пакета](./checks) і [передачі](./handoff).
