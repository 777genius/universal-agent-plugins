# Перевірка пакета та його доказів {#check-a-package-and-its-evidence}

**Розробка у збірці з вихідного коду:** ці команди `agentplugins author`
потребують [збірки з увімкненими інструментами розробки](./#build-from-source).
Поточний випуск інсталятора їх не містить. Запускайте відносні приклади з
батьківської папки пакета та завжди використовуйте той самий точний корінь.

## Виконайте автономний цикл перевірок розробки {#run-the-offline-authoring-loop}

```bash
agentplugins author validate ./review-helper
agentplugins author inspect ./review-helper
agentplugins author test ./review-helper
```

Перевірка валідації оцінює зафіксовану стандартну конфігурацію та готовність
пакета до розробки. Огляд показує компоненти й невиконані вимоги. `test` без
прапорців виконання статично перевіряє конфігурацію, гігієну пакета, Skills та
MCP. Ці команди не запускають сервери й не виконують інструкції Skill.

## Розрізняйте рівні доказів {#read-the-evidence-layers}

| Рівень | Що підтверджує | Що потребує іншої перевірки |
| --- | --- | --- |
| Відповідність | Зафіксовані стандартні дані відповідають вбудованим схемам і профілю. | Корисна поведінка в конкретному агенті. |
| Безпека хоста | Вхідні дані проходять обмежені перевірки файлової системи та хоста. | Дозвіл користувача на встановлення чи виконання. |
| Готовність | Наявні докази задовольняють перевірену політику. | Схвалення публічного випуску чи прийняття платформою. |
| Сумісність | Статична підтримка обраних клієнтів і компонентів. | Фактичне виявлення й активація в реальному клієнті. |
| Інструментарій | Обмежені метадані проєкту, нативних файлів і виконуваних файлів. | Визначення залежностей та запуск сервера. |
| Виконання | Явно запущена перевірка MCP звітує про спостережені етапи. | Інші інструменти, клієнти, потоки OAuth чи неперевірені середовища. |

Оцінюйте відповідність та загальну готовність окремо. Коректний маніфест може
мати неповні докази компонентів або хоста. Зберігайте позначку «не оцінено»,
не перетворюючи її на успіх.

## Обирайте клієнти явно {#select-clients-explicitly}

```bash
agentplugins author compat ./review-helper --target codex,claude
agentplugins author inspect ./review-helper --target codex,claude
agentplugins author doctor ./review-helper
agentplugins author capabilities
```

`compat` потребує різних ідентифікаторів клієнтів через кому; `all` не
підтримується. Ці статичні перевірки не потребують установлених клієнтів.
Doctor досліджує зафіксовані нативні файли й метадані виконуваних файлів без
запуску процесів чи мережі. Capabilities показує схеми, метадані клієнтів і
реалізовані команди цього рушія; він не сертифікує пакет і не встановлює
кваліфікацію публічного випуску.

## Перевіряйте виконання MCP явно {#evaluate-mcp-runtime-explicitly}

Локальне виконання stdio наразі потребує Linux, системного bubblewrap і Node
у системних каталогах виконання. До запуску мають успішно пройти попередні
перевірки ізоляції процесів (зокрема делегованої cgroup v2) та просторів імен
bubblewrap. Див. [передумови stdio](./mcp-stdio). Виконання Streamable HTTP не
використовує цю локальну пісочницю процесів і потребує окремого явного дозволу
на мережу.

Для пакета з [посібника stdio](./mcp-stdio) окремо встановіть розпізнані
зафіксовані залежності, а потім оберіть точну назву сервера з `mcp.json`:

```bash
agentplugins author test ./local-tools --runtime mcp --server local-tools
```

Ця команда з вихідного коду запускає обраний MCP-процес і перевіряє ініціалізацію
та виявлення інструментів. Для виклику інструмента потрібні обидва параметри:
`--tool` і `--fixture`. Файл прикладу — JSON-об'єкт відносно пакета з аргументами
цього інструмента. Для `hello` із шаблону створіть `fixtures/hello.json` із `{}`:

```bash
agentplugins author test ./local-tools --runtime mcp --server local-tools \
  --tool hello --fixture fixtures/hello.json
```

Для Streamable HTTP явно дозвольте мережевий доступ:

```bash
agentplugins author test ./docs-service --runtime mcp --server docs-service \
  --allow-network
```

Використовуйте справжній ідентифікатор сервера зі свого пакета. Типовий час
очікування — десять секунд; `--deadline` приймає додатну тривалість до однієї
хвилини. Окремо оцінюйте докази ініціалізації, інструментів, необов'язкового
виклику та очищення. Успіх виконання тут не є виконанням через установленого
агента й не доводить OAuth, інші інструменти або публічне розгортання.

## Працюйте ітеративно в циклі розробки {#iterate-with-the-source-development-loop}

```bash
agentplugins author dev ./local-tools --server local-tools
```

`dev` запускає обмежені цикли MCP у відповідь на зміни пакета; зупиніть його
через Ctrl+C. Використовуйте `--once` для одного циклу та під час запиту JSON.
Віддалені сервери потребують `--allow-network`; виклики інструментів, як і
раніше, потребують явної пари інструмент/файл прикладу. Команда не встановлює
пакет у нативний клієнт.

## Збережіть звіт для перевірки {#capture-a-reviewable-report}

```bash
agentplugins author validate ./review-helper --format json
agentplugins author inspect ./review-helper --format json
```

Для виводу, призначеного людині, використовуйте `--format human`, а за потреби
`--no-color`. `--include-root` розкриває обраний корінь; у спільній діагностиці
уникайте зайвих приватних шляхів. `--release-policy` додає обмежені перевірки
гігієни випуску до перевірок пакета та не є дозволом на публікацію. Підкоманди
Skills мають вужчий набір прапорців; читайте їхню власну довідку.

## Змінюйте JSON свідомо {#maintain-json-deliberately}

Поточний вихідний код може спланувати детерміновану нормалізацію одного
обраного стандартного файлу й записати його лише з явним `--write`:

```bash
agentplugins author normalize ./review-helper --document plugin.json
agentplugins author normalize ./review-helper --document plugin.json --write
```

Оберіть натомість `mcp.json`, якщо хочете нормалізувати саме його. Нативний
імпорт читає один явно обраний файл Claude MCP у строгому JSON; профілі не
шукаються. Поточний імпортер приймає лише безпечні записи stdio з `command` та
необов'язковим `args`; записи HTTP/URL, `env` та додаткові поля сервера
пропускаються, навіть якщо початковий клієнт їх приймає. Перед застосуванням
сплануйте нове, ще неіснуюче місце призначення з абсолютним шляхом:

```bash
agentplugins author import native ./claude.json --from claude \
  --output /absolute/path/to/new-plugin --name new-plugin \
  --description 'Імпортований пакет Claude MCP'
```

Перевірте безпечні та пропущені сервери й непідтримувані поля. Додайте `--write`,
щоб записати перевірений пакет у це відсутнє місце призначення. Небезпечні сервери
та сервери з обліковими даними пропускаються; дослідіть результат, не припускаючи,
що перенесено кожен початковий сервер. Імпорт інших нативних клієнтів тут не
надається.

## Розрізняйте призначення команд {#choose-the-right-command-boundary}

Команда інсталятора `agentplugins validate ./review-helper` читає пакет для
встановлення; `agentplugins doctor` діагностує керований стан. Вони відрізняються
від операцій розробки у збірці з вихідного коду. Прапорці області та безпеки
інсталятора не стають прапорцями розробки. Init створює реальні файли;
нормалізація та імпорт потребують `--write` для застосування планів.
Продовжуйте з [передачі пакета](./handoff).
