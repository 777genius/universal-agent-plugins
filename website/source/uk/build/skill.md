# Створення окремого Skill {#build-a-standalone-skill}

**Розробка у збірці з вихідного коду:** команди на цій сторінці потребують
[збірки з увімкненими інструментами розробки](./#build-from-source).
Поточний випуск інсталятора не містить `agentplugins author`.

Оберіть цей шлях, якщо агенту потрібен повторюваний метод, контрольний список
або інструкція з написання тексту, а з'єднання з MCP-інструментом не потрібне.
Пакет містить один Skill і кореневий маніфест. Для етапів розробки не потрібні
сервер, встановлення середовища виконання або профіль клієнта.

## Оберіть явне місце призначення {#choose-an-explicit-destination}

Приклади передбачають, що поточний каталог — тимчасовий батьківський каталог,
а `./review-helper` ще не існує. Оберіть переносну назву пакета малими літерами.
Шлях задає місце призначення; `--name` — назву пакета в маніфесті.

```bash
agentplugins author init ./review-helper \
  --template skill \
  --name review-helper \
  --description 'Перевірка змін документації на зрозумілість і підтвердженість' \
  --skill-name review-docs
```

Init потребує відсутнього місця призначення та не перезаписує наявний каталог.
Якщо після запису результату повідомлено про подальшу помилку, дослідіть
результат перед повтором. Цей процес не має прапорця перезапису.

## Перегляньте створені файли {#review-the-created-files}

```text
review-helper/
  plugin.json
  README.md
  .gitignore
  skills/
    review-docs/
      SKILL.md
```

Згенерований Skill — початкова інструкція. Замініть основний текст конкретним
методом, корисним вашим користувачам. Назва Skill має відповідати каталогу.
Наприклад, основний текст `skills/review-docs/SKILL.md` може бути таким:

```markdown
# Перевірка змін документації

Застосовуйте цей Skill для перевірки змін документації перед передачею.

1. Визначте цільового читача й задачу, яку сторінка допомагає виконати.
2. Переконайтеся, що кожна команда називає вхідні дані та описує свою дію.
3. Відокремте підтверджену поведінку від передумов і неперевірених тверджень.
4. Повідомте про незрозумілі інструкції та запропонуйте текст на заміну.

Поверніть стислий список зауважень із розташуванням у файлах. Якщо проблем
не знайдено, зазначте перевірені сторінки та перевірки, які не входили до огляду.
```

Збережіть згенерований блок метаданих над цим текстом. Його `name` і
`description` ідентифікують Skill та допомагають агенту вирішувати, коли його
застосовувати. Інструкції Skill не надають дозволу запускати скрипти чи
отримувати доступ до приватних ресурсів.

## Перевірте точний корінь пакета {#check-the-exact-package-root}

```bash
agentplugins author validate ./review-helper
agentplugins author skills validate ./review-helper
agentplugins author inspect ./review-helper
agentplugins author test ./review-helper
```

Ці перевірки статичні. Вони не просять агента виконувати інструкції та не
оцінюють якість його відповіді.

Окремо оцінюйте відповідність і готовність у звіті. Навіть правильно оформлений
Skill потребує перевірки людиною на корисність, точність та доречні межі.

Продовжуйте з [додаткових Skills](./skills), [перевірок клієнтів](./checks)
або [передачі локальному інсталятору](./handoff). Щоб поєднати інструменти та
інструкції, оберіть [гібридний шлях](./hybrid) для нового пакета.
