# Створення пакета stdio MCP {#build-a-stdio-mcp-package}

**Розробка у збірці з вихідного коду:** наведені команди потребують
[збірки з увімкненими інструментами розробки](./#build-from-source).
Поточний випуск інсталятора їх не містить.

Оберіть stdio, якщо пакет надає локальний процес, який обмінюється даними через
стандартний ввід і вивід. Заготовка підтримує Node.js 22 або новіший і використовує
офіційний MCP SDK. Її створення не встановлює залежності та не запускає сервер.

## Створіть заготовку {#create-the-scaffold}

Оберіть ще неіснуюче місце призначення в наявному батьківському каталозі:

```bash
agentplugins author init ./local-tools \
  --template mcp-stdio \
  --name local-tools \
  --description 'Надання локальних інструментів через MCP-сервер Node' \
  --runtime node
```

`node` — підтримуване значення середовища виконання для цього переносного
шаблону. Прапорці середовищ Python або Go не входять до поточного інтерфейсу
цієї команди.

## Перегляньте файли {#review-the-files}

```text
local-tools/
  plugin.json
  mcp.json
  package.json
  package-lock.json
  src/
    server.mjs
  README.md
  .gitignore
```

`mcp.json` оголошує сервер `local-tools` із командою `node` та аргументом
`${PLUGIN_ROOT}/src/server.mjs`. Токен пакета розкривається в межах обраного
пакета; він не означає поточний каталог вашої оболонки. Вихідний код починається
з невеликого інструмента `hello`. Адаптуйте його до своєї задачі та надсилайте
журнали застосунку в stderr, щоб stdout залишався для протоколу MCP.

Перегляньте маніфест залежностей і файл фіксації. Init записує їх, але не
запускає npm та не доводить, що хост може імпортувати SDK.

## Зберіть статичні докази {#gather-static-evidence}

```bash
agentplugins author validate ./local-tools
agentplugins author inspect ./local-tools
agentplugins author test ./local-tools
agentplugins author compat ./local-tools --target codex,claude
agentplugins author doctor ./local-tools
```

Це статичні перевірки. Doctor досліджує обмежені метадані проєкту та виконуваних
файлів; він не доводить установлені залежності, успішне узгодження протоколу
чи працездатність інструмента. Розрізняйте [рівні доказів](./checks).

## Установіть залежності розпізнаного шаблону {#bootstrap-the-recognized-template}

Для згенерованої структури Node з відповідним файлом фіксації поточний вихідний
код може показати план і встановити залежності:

```bash
agentplugins author bootstrap ./local-tools --dry-run
agentplugins author bootstrap ./local-tools
```

Застосування bootstrap наразі потребує Linux і підтримки файлової системи з
прив'язкою до дескрипторів; інші платформи повідомляють
`bootstrap_platform_unsupported`. Попередній перегляд усе ж може дослідити
розпізнану структуру без встановлення залежностей.

Перед застосуванням перегляньте план. Bootstrap використовує встановлення npm
за файлом фіксації з вимкненими скриптами життєвого циклу. Він приймає розпізнану
згенеровану структуру, узгоджені файли пакета та відсутній `node_modules`;
це не універсальна заміна менеджера пакетів. Змінені файли залежностей,
конкуруючі файли фіксації або наявні результати можуть спричинити відмову.
Виконайте зазначені вимоги до структури замість додавання прапорця перезапису.
Отримання залежностей може використовувати мережу.

## Запустіть одну явну перевірку MCP {#run-one-explicit-mcp-check}

Локальне виконання stdio наразі потребує Linux, системного `bwrap` (bubblewrap),
робочої ізоляції процесів (зокрема делегованої cgroup v2), підтримки просторів
імен і Node у системних каталогах виконання (`/usr`, `/bin`, `/lib` або `/lib64`).
До запуску коду пакета команда вимагає успішних перевірок ізоляції процесів і
bubblewrap та відмовляє на хостах, де не може їх забезпечити. Node у каталозі
користувацького менеджера версій не задовольняє цей контракт виконання.
Статичні перевірки доступні окремо.

```bash
agentplugins author test ./local-tools --runtime mcp --server local-tools
```

Це запускає обраний локальний процес і перевіряє ініціалізацію MCP та виявлення
інструментів. Для виклику `hello` потрібен явний JSON-файл аргументів; див.
[приклад перевірки виконання](./checks#evaluate-mcp-runtime-explicitly).
Для постійної ітеративної роботи:

```bash
agentplugins author dev ./local-tools --server local-tools
```

Зберігайте точні ідентифікаційні дані рушія, пакета й платформи в результатах
виконання. Пряма перевірка розробки не доводить, що той самий сервер працює
через кожного нативного агента чи що клієнт надав довіру або завершив
автентифікацію.

## Підготуйте передачу {#prepare-the-handoff}

Опишіть інструменти, вимогу Node.js, файли залежностей та докази виконання
у README. Укажіть обраний сервер і всі неперевірені інструменти чи середовища.
Потім передайте пакет через [передачу інсталятору](./handoff). Якщо користувачам
потрібні настанови поряд з інструментами, додайте інструкції через
[додаткові Skills](./skills).
