# पैकेज और उसके प्रमाण जाँचें {#check-a-package-and-its-evidence}

**सोर्स बिल्ड में पैकेज निर्माण:** इन `agentplugins author` कमांड के लिए [पैकेज निर्माण की सुविधा वाले सोर्स बिल्ड](./#build-from-source) चाहिए। वे वर्तमान इंस्टॉलर रिलीज़ में शामिल नहीं हैं। सापेक्ष पाथ वाले उदाहरण पैकेज के पैरेंट फ़ोल्डर से चलाएँ और पूरी प्रक्रिया में वही सटीक रूट रखें।

## ऑफ़लाइन पैकेज निर्माण चक्र चलाएँ {#run-the-offline-authoring-loop}

```bash
agentplugins author validate ./review-helper
agentplugins author inspect ./review-helper
agentplugins author test ./review-helper
```

वैलिडेशन पढ़े गए मानक कॉन्फ़िगरेशन और पैकेज निर्माण की तैयारी जाँचता है। निरीक्षण घटक और अनसुलझी आवश्यकताएँ दिखाता है। रनटाइम फ़्लैग के बिना `test` कॉन्फ़िगरेशन, स्वच्छता, Skills और MCP की स्थिर जाँच करता है। ये कमांड सर्वर शुरू नहीं करतीं और Skill के निर्देश नहीं चलातीं।

## प्रमाण की परतें पढ़ें {#read-the-evidence-layers}

| परत | क्या सिद्ध होता है | किसके लिए दूसरी जाँच चाहिए |
| --- | --- | --- |
| अनुपालन | पढ़ा गया मानक डेटा अंतर्निहित स्कीमा/प्रोफ़ाइल के अनुसार है। | किसी विशिष्ट एजेंट में उपयोगी व्यवहार। |
| होस्ट सुरक्षा | इनपुट सीमित फ़ाइल सिस्टम और होस्ट जाँचें पूरी करता है। | इंस्टॉलेशन या निष्पादन के लिए उपयोगकर्ता की अनुमति। |
| तैयारी | उपलब्ध प्रमाण जाँची गई नीति पूरी करते हैं। | सार्वजनिक रिलीज़ अनुमोदन या प्लेटफ़ॉर्म की स्वीकृति। |
| संगतता | चुने हुए टार्गेट और घटकों के लिए स्थिर समर्थन। | वास्तविक क्लाइंट में प्रभावी पहचान और सक्रियण। |
| टूलचेन | सीमित प्रोजेक्ट, नेटिव फ़ाइल और एक्ज़ीक्यूटेबल मेटाडेटा। | निर्भरता हल करना और सर्वर शुरू होना। |
| रनटाइम | स्पष्ट रूप से चलाई MCP जाँच देखे गए चरण बताती है। | दूसरे टूल, क्लाइंट, OAuth प्रवाह या न जाँचे परिवेश। |

अनुपालन और कुल तैयारी अलग पढ़ें। वैध मेनिफ़ेस्ट में भी घटक या होस्ट के प्रमाण अधूरे हो सकते हैं। “मूल्यांकन नहीं हुआ” को पास मानने के बजाय स्पष्ट बनाए रखें।

## क्लाइंट स्पष्ट चुनें {#select-clients-explicitly}

```bash
agentplugins author compat ./review-helper --target codex,claude
agentplugins author inspect ./review-helper --target codex,claude
agentplugins author doctor ./review-helper
agentplugins author capabilities
```

`compat` को कॉमा से अलग किए गए अलग-अलग टार्गेट ID चाहिए; वह `all` स्वीकार नहीं करता। इन स्थिर जाँचों के लिए क्लाइंट इंस्टॉल होना आवश्यक नहीं है। Doctor बिना प्रक्रिया या नेटवर्क के पढ़ी गई नेटिव फ़ाइलें और एक्ज़ीक्यूटेबल मेटाडेटा देखता है। Capabilities इंजन के स्कीमा, क्लाइंट मेटाडेटा और लागू कमांड बताता है; यह किसी पैकेज को प्रमाणित नहीं करता और न सार्वजनिक रिलीज़ योग्यता स्थापित करता है।

## MCP रनटाइम स्पष्ट रूप से जाँचें {#evaluate-mcp-runtime-explicitly}

लोकल stdio रनटाइम के लिए अभी Linux, सिस्टम bubblewrap और सिस्टम रनटाइम डायरेक्टरी के भीतर Node चाहिए। प्रक्रिया नियंत्रण (delegated cgroup v2 सहित) और bubblewrap नेमस्पेस की शुरुआती जाँचें लॉन्च से पहले सफल होनी चाहिए। [Stdio पूर्वापेक्षाएँ](./mcp-stdio) देखें। Streamable HTTP रनटाइम इस लोकल प्रक्रिया सैंडबॉक्स का इस्तेमाल नहीं करता और उसे नेटवर्क की अलग स्पष्ट अनुमति चाहिए।

[Stdio ट्यूटोरियल](./mcp-stdio) से बने पैकेज के लिए उसकी पहचानी गई लॉक निर्भरताएँ अलग इंस्टॉल करें, फिर `mcp.json` से सटीक सर्वर नाम चुनें:

```bash
agentplugins author test ./local-tools --runtime mcp --server local-tools
```

यह सोर्स कमांड चुनी हुई MCP प्रक्रिया चलाती है और प्रारंभिकरण तथा टूल खोज जाँचती है। टूल कॉल करने के लिए `--tool` और `--fixture` दोनों दें। फ़िक्स्चर पैकेज-सापेक्ष JSON ऑब्जेक्ट है जिसमें उस टूल के आर्ग्युमेंट होते हैं। टेम्प्लेट के `hello` टूल के लिए `{}` वाला `fixtures/hello.json` बनाएँ:

```bash
agentplugins author test ./local-tools --runtime mcp --server local-tools \
  --tool hello --fixture fixtures/hello.json
```

Streamable HTTP के लिए नेटवर्क की स्पष्ट अनुमति दें:

```bash
agentplugins author test ./docs-service --runtime mcp --server docs-service \
  --allow-network
```

अपने पैकेज की वास्तविक सर्वर पहचान इस्तेमाल करें। समय सीमा डिफ़ॉल्ट रूप से दस सेकंड है। `--deadline` से अधिकतम एक मिनट की धनात्मक अवधि दी जा सकती है। प्रारंभिकरण, टूल, वैकल्पिक टूल कॉल और सफ़ाई के प्रमाण अलग-अलग देखें। यहाँ रनटाइम पास होना इंस्टॉल किए एजेंट के माध्यम से निष्पादन नहीं है और OAuth, दूसरे टूल या सार्वजनिक डिप्लॉयमेंट सिद्ध नहीं करता।

## सोर्स विकास चक्र में सुधार करें {#iterate-with-the-source-development-loop}

```bash
agentplugins author dev ./local-tools --server local-tools
```

पैकेज बदलने पर `dev` सीमित MCP चक्र चलाता है; Ctrl+C से रोकें। एक चक्र और JSON आउटपुट के लिए `--once` दें। दूरस्थ सर्वर को `--allow-network` चाहिए; टूल कॉल के लिए अब भी स्पष्ट tool/fixture जोड़ी आवश्यक है। यह कमांड नेटिव क्लाइंट में इंस्टॉल नहीं करती।

## समीक्षा योग्य रिपोर्ट बनाएँ {#capture-a-reviewable-report}

```bash
agentplugins author validate ./review-helper --format json
agentplugins author inspect ./review-helper --format json
```

मानव-पठनीय आउटपुट के लिए `--format human` और ज़रूरत हो तो `--no-color` दें। `--include-root` चुना गया रूट दिखाता है; साझा निदान में अनावश्यक निजी पाथ न दें। `--release-policy` पैकेज जाँचों में सीमित रिलीज़ स्वच्छता जाँच जोड़ता है; यह प्रकाशन अनुमोदन नहीं है। Skills उपकमांड कम फ़्लैग स्वीकार करती हैं; उनकी अपनी help देखें।

## JSON में सोच-समझकर रखरखाव करें {#maintain-json-deliberately}

वर्तमान सोर्स एक चुनी हुई मानक फ़ाइल के नियत सामान्यीकरण की योजना बना सकता है और केवल स्पष्ट `--write` के साथ लिखता है:

```bash
agentplugins author normalize ./review-helper --document plugin.json
agentplugins author normalize ./review-helper --document plugin.json --write
```

यदि `mcp.json` सामान्यीकृत करना चाहते हों तो वही चुनें। नेटिव इम्पोर्ट एक स्पष्ट strict-JSON Claude MCP फ़ाइल पढ़ता है; प्रोफ़ाइल नहीं खोजता। वर्तमान इम्पोर्टर केवल सुरक्षित stdio एंट्री स्वीकार करता है जिनमें `command` और वैकल्पिक `args` हों। HTTP/URL एंट्री, `env` और अतिरिक्त सर्वर फ़ील्ड छोड़ दिए जाते हैं, भले स्रोत क्लाइंट उन्हें स्वीकार करता हो। लागू करने से पहले नया, अनुपस्थित पूर्ण गंतव्य पाथ चुनकर योजना बनाएँ:

```bash
agentplugins author import native ./claude.json --from claude \
  --output /absolute/path/to/new-plugin --name new-plugin \
  --description 'Imported Claude MCP package'
```

सुरक्षित/छोड़े गए सर्वर और असमर्थित फ़ील्ड की समीक्षा करें। वैलिडेट किया पैकेज उस अनुपस्थित गंतव्य पर लिखने के लिए `--write` जोड़ें। असुरक्षित या क्रेडेंशियल वाले सर्वर छोड़ दिए जाते हैं; यह मानने के बजाय कि हर मूल सर्वर आ गया, परिणाम देखें। यहाँ किसी दूसरे नेटिव क्लाइंट का इम्पोर्ट उपलब्ध नहीं है।

## सही कमांड सीमा चुनें {#choose-the-right-command-boundary}

इंस्टॉलर का `agentplugins validate ./review-helper` इंस्टॉलेशन के लिए पैकेज पढ़ता है; `agentplugins doctor` प्रबंधित स्थिति का निदान करता है। ये सोर्स बिल्ड में पैकेज निर्माण कार्रवाइयों से अलग हैं। इंस्टॉलर के स्कोप और सुरक्षा फ़्लैग पैकेज निर्माण फ़्लैग नहीं बन जाते। Init वास्तविक फ़ाइलें बनाता है; सामान्यीकरण और इम्पोर्ट की योजना लागू करने के लिए `--write` आवश्यक है। आगे [पैकेज सौंपना](./handoff) देखें।
