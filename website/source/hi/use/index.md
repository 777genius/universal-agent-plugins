# प्लगइन इस्तेमाल करें {#use-plugins}

Universal Agent Plugins आपके चुने हुए AI एजेंटों के लिए मानक पैकेज इंस्टॉल करता है। पैकेज में Skills, MCP सर्वर कॉन्फ़िगरेशन या दोनों हो सकते हैं। आप अपने खाते के लिए इंस्टॉल कर सकते हैं या किसी प्रोजेक्ट की निर्भरताएँ अलग रख सकते हैं।

## CLI प्राप्त करें {#get-the-cli}

Node.js 22 या उसके बाद के संस्करण के साथ npm रैपर सीधे चलाएँ:

```bash
npx universal-agent-plugins search docs
```

बार-बार इस्तेमाल के लिए इसे ग्लोबली इंस्टॉल करें:

```bash
npm install -g universal-agent-plugins
agentplugins version
```

Homebrew भी एक विकल्प है:

```bash
brew install 777genius/agentplugins/agentplugins
```

[नेटिव इंस्टॉलेशन गाइड](https://github.com/777genius/universal-agent-plugins/blob/main/docs/NATIVE_INSTALL.md) में macOS, Linux और Windows के निर्देश हैं। नेटिव मैनेजर के लिए Node.js आवश्यक नहीं है, हालाँकि अलग-अलग प्लगइन को अपना रनटाइम चाहिए हो सकता है। इन निर्देशों के उदाहरण `agentplugins` का इस्तेमाल करते हैं; `npx universal-agent-plugins` से भी वही इंस्टॉलर कमांड चलाई जा सकती हैं।

## इंस्टॉलेशन के चरण पूरे करें {#follow-the-installation-journey}

1. [पैकेज खोजें और उसकी जाँच करें](./install)। उसके स्रोत और पूर्वापेक्षाएँ देखें।
2. `--dry-run` से इच्छित टार्गेट और स्कोप का पूर्वावलोकन देखें।
3. समीक्षा की गई इंस्टॉलेशन लागू करें और सक्रियण के निर्देश पूरे करें।
4. सूची, अपडेट, रिपेयर और हटाने की कमांड से [इंस्टॉल की गई स्थिति का रखरखाव करें](./manage)।
5. ज़रूरत पड़ने पर `uap.toml` और `uap.lock` से साझा निर्भरता सेट बहाल करें।

[CLI 0.1.94](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.94) वर्तमान नेटिव इंस्टॉलर है। पैकेज मैनेजर चैनल पीछे रह सकते हैं; 0.1.94 के व्यवहार पर निर्भर होने से पहले `agentplugins version` जाँचें। चुना गया चैनल पुराना हो तो नेटिव इंस्टॉलर या Homebrew इस्तेमाल करें। स्पष्ट प्रोजेक्ट स्कोप 0.1.93 से उपलब्ध है। अधिकांश कमांड डिफ़ॉल्ट रूप से उपयोगकर्ता स्कोप चुनती हैं। 0.1.94 से, स्रोत आर्ग्युमेंट या स्पष्ट स्कोप के बिना `install` प्रोजेक्ट तभी चुनता है जब ठीक वर्तमान फ़ोल्डर में नियमित `uap.toml` फ़ाइल हो; वह पैरेंट फ़ोल्डर नहीं खोजता। प्रोजेक्ट के रखरखाव की कमांड में `--scope project` चुनें। प्रोजेक्ट समर्थन और क्लाइंट सक्रियण टार्गेट के अनुसार बदलते हैं।

## परिणाम को सही स्तर पर पढ़ें {#read-the-result-at-the-right-level}

इंस्टॉलेशन के बाद भी क्लाइंट रीलोड, ट्रस्ट प्रॉम्प्ट, मैन्युअल सक्रियण या OAuth चरण बाकी हो सकता है। **Prepared** परिणाम का अर्थ है कि क्लाइंट में काम अभी बाकी है। पूरी कार्रवाई को रनटाइम सफलता का प्रमाण मानने के बजाय हर टार्गेट का परिणाम पढ़ें। संस्करण-विशिष्ट नेटिव अवलोकनों के प्रमाण के लिए [क्लाइंट संगतता](../reference/client-compatibility) देखें।

## यदि आप पैकेज लिख रहे हैं {#if-you-are-writing-a-package}

[प्लगइन बनाएँ](../build/) से शुरू करें। साझा की जाने वाली इकाई एक डायरेक्टरी है, जिसके रूट में `plugin.json` और उसके घटक हों। इंस्टॉलर इस्तेमाल करने वाले व्यक्ति को सोर्स से बने पैकेज निर्माण टूल चलाने की ज़रूरत नहीं होती।

| कमांड | उद्देश्य |
| --- | --- |
| `agentplugins validate ./my-plugin` | इंस्टॉलेशन के लिए लोकल पैकेज पढ़ना और वैलिडेट करना। |
| `agentplugins doctor` | इंस्टॉलर द्वारा प्रबंधित स्थिति का निदान करना। |
| `agentplugins author validate ./my-plugin` | पैकेज निर्माण की सुविधा वाले सोर्स बिल्ड में मानक अनुपालन और तैयारी जाँचना। |
| `agentplugins author doctor ./my-plugin` | उसी सोर्स बिल्ड में प्रोजेक्ट और टूलचेन के प्रमाण देखना। |

वर्तमान npm और नेटिव इंस्टॉलर रिलीज़ में `agentplugins author` शामिल नहीं है।
