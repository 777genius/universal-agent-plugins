# प्लगइन खोजें और इंस्टॉल करें {#find-and-install-a-plugin}

ऐसा पैकेज चुनें जिसका स्रोत और उद्देश्य आप समझते हों। नीचे दी गई कमांड प्रकाशित इंस्टॉलर इस्तेमाल करती हैं। यदि `agentplugins` अभी उपलब्ध नहीं है, तो [CLI इंस्टॉलेशन](./) देखें। बदलाव लागू करने से पहले `--dry-run` से योजना की समीक्षा करें।

## पैकेज खोजें {#discover-the-package}

```bash
agentplugins search docs
agentplugins info context7
```

`context7` जैसा छोटा नाम हस्ताक्षरित Universal Agent Plugins Registry से आता है। खोज और पैकेज की जानकारी उपयुक्त विकल्प चुनने में मदद करती हैं; वे पैकेज चलाती नहीं हैं और न ही सेवा की उपलब्धता सिद्ध करती हैं। इंस्टॉल करने से पहले उपलब्ध टूल, Skills, रनटाइम आवश्यकताओं और खाते की पहुँच की समीक्षा करें।

## एक स्पष्ट चयन का पूर्वावलोकन देखें {#preview-one-explicit-selection}

```bash
agentplugins add context7 --target codex,cursor --dry-run
```

स्रोत, चुने गए टार्गेट, गंतव्य, सुरक्षा निष्कर्ष और बाकी सक्रियण कार्य की समीक्षा करें। यह कमांड इंस्टॉलेशन लागू किए बिना योजना दिखाती है। यह MCP सर्वर का परीक्षण नहीं करती।

## योजना की समीक्षा के बाद इंस्टॉल करें {#install-after-reviewing-the-plan}

```bash
agentplugins add context7 --target codex,cursor
```

इंटरैक्टिव चयन के लिए `--target` छोड़ दें। CLI पहचाने गए एक एजेंट को अपने-आप चुन सकता है या कई एजेंट उपलब्ध हों तो चयन सूची दिखा सकता है। दोहराए जा सकने वाले चयन और ऑटोमेशन में स्पष्ट टार्गेट इस्तेमाल करें।

इंस्टॉलर चुने गए क्लाइंट की शुरुआती जाँच करता है और उन फ़ाइलों को सुरक्षित रखता है जिनका स्वामित्व उसके पास नहीं है। यदि कार्रवाई में असफल रोलबैक या लंबित रिकवरी बताई जाए, तो रिपोर्ट सँभालें और दोबारा प्रयास करने से पहले रिकवरी के निर्देश पूरे करें।

## सक्रियण पूरा करें {#finish-activation}

परिणाम में दिए गए क्लाइंट-विशिष्ट चरण पूरे करें: रीलोड, नया सत्र, वर्कस्पेस ट्रस्ट, साइन-इन या स्पष्ट सक्रियण बाकी हो सकता है। तैयार फ़ाइलें और सफल नेटिव पंजीकरण OAuth या सफल टूल कॉल सिद्ध नहीं करते। इंस्टॉलेशन गायब हो या बदली हुई मिले तो [प्रबंधित स्थिति का निदान](./manage) करें। पैकेज मौजूद होने पर भी उपलब्ध न हो, तो क्लाइंट में प्रमाणीकरण जाँचें।

## लोकल पैकेज इस्तेमाल करें {#use-a-local-package}

वह डायरेक्टरी चुनें जिसके रूट में `plugin.json` हो:

```bash
agentplugins validate ./my-plugin
agentplugins add ./my-plugin --target codex --dry-run
```

इंस्टॉलर वैलिडेशन और योजना पर भी सुरक्षा नीति लागू होती है। लोकल पैकेज के लिए भी सुरक्षा मेटाडेटा या पिन किया गया स्कैनर डाउनलोड हो सकता है। `--dry-run` प्रबंधित इंस्टॉलेशन के बदलाव रोकता है; यह पूरी कार्रवाई के ऑफ़लाइन होने का वादा नहीं करता।

योजना की समीक्षा के बाद इंस्टॉल करने के लिए `--dry-run` छोड़ दें। लोकल डायरेक्टरी की इंस्टॉलेशन लोकल ही रहती है; यह ऐसी पोर्टेबल निर्भरता नहीं बनती जिसे दूसरी मशीन प्राप्त कर सके। लेखक से [पैकेज सौंपने के प्रमाण](../build/handoff) माँगें।

## सटीक GitHub स्रोत चुनें {#select-an-exact-github-source}

स्थापित अपरिवर्तनीय GitHub सिंटैक्स के लिए पूरा 40-अक्षर का कमिट SHA आवश्यक है। इस उदाहरण को वास्तविक रिपॉज़िटरी, समीक्षा किए गए रिविज़न और पैकेज पाथ से बदलें:

```text
agentplugins add owner/repository@0123456789abcdef0123456789abcdef01234567//path/to/plugin --target codex --dry-run
```

`owner/repository@...` वाला रूप ब्रांच, टैग और छोटे SHA स्वीकार नहीं करता। पाथ न देने पर इंस्टॉलर वैध रूट पैकेज या एकमात्र वैध नेस्टेड पैकेज चुनता है। कई विकल्प हों तो स्पष्ट पाथ चाहिए। संभावित पैकेज 16 से अधिक हों तो विकल्पों को प्राप्त करने से पहले ही पाथ देना आवश्यक है। रिपेयर दर्ज स्रोत को दोहराता है। अपरिवर्तनीय इंस्टॉलेशन को दूसरे स्रोत पर ले जाना अलग स्रोत-चयन कार्रवाई है।

CLI 0.1.93 सीधे HTTPS Git, SSH, समर्थित प्रदाताओं के ब्राउज़र URL और पूरे HTTPS/लोकल आर्काइव भी स्वीकार करता है। उदाहरण के लिए, इन प्लेसहोल्डर को समीक्षा किए गए पैकेज स्रोतों से बदलें:

```text
agentplugins add 'https://git.example.com/team/tools.git#refs/heads/main//plugins/demo' --target codex --dry-run
agentplugins add 'ssh://git@git.example.com/team/tools.git#main//plugins/demo' --target codex --dry-run
agentplugins add 'https://downloads.example.com/plugin.tar.gz' --target codex --dry-run
```

Git मौजूदा नेटिव क्रेडेंशियल और SSH होस्ट ट्रस्ट इस्तेमाल करता है। HTTPS आर्काइव बिना क्रेडेंशियल प्राप्त किए जाते हैं और उनमें पूरा मानक पैकेज होना चाहिए। लॉक सटीक Git रिविज़न या मूल आर्काइव बाइट के साथ पैकेज डाइजेस्ट पिन करता है। बदलने वाला स्रोत स्पष्ट अपडेट से आगे बढ़ सकता है; लॉक के अनुसार बहाली वही पिन रखती है। पूरे पैकेज के ये स्रोत अलग Skills प्राप्त करने से भिन्न हैं। प्रदाता सिंटैक्स, पैकेज चयन, चेकसम और एक्सट्रैक्शन सीमाओं के लिए [सीधे पूरे पैकेज के स्रोत](https://github.com/777genius/universal-agent-plugins/blob/main/docs/DIRECT_PACKAGE_SOURCES.md) पढ़ें।

## Agent Skills इंस्टॉल करें {#install-agent-skills}

किसी सार्वजनिक GitHub रिपॉज़िटरी, फ़ोल्डर या `SKILL.md` URL, या पूरी `.well-known` Skills इंडेक्स देने वाले HTTPS प्रकाशक से अलग Skills के लिए `skills` कमांड समूह इस्तेमाल करें:

```bash
agentplugins skills add owner/repository --ui
```

`owner/repository` की जगह वास्तविक स्रोत दें। `--ui` साथ में उपलब्ध ब्राउज़र चयन इंटरफ़ेस खोलता है और उसे इंटरैक्टिव टर्मिनल चाहिए। टर्मिनल में चयन के लिए `--no-ui` इस्तेमाल करें। स्पष्ट चयन के लिए:

```bash
agentplugins skills add owner/repository --skill review --skill pdf \
  --target codex,claude --no-ui --yes
```

- सटीक नामों के लिए `--skill` दोहराएँ। नाम अस्पष्ट हो तो रिपॉज़िटरी से संबंधित सटीक Skill फ़ोल्डर के लिए `--path` दें।
- URL की सीमा अस्पष्ट हो तो `--ref` सटीक Git ref चुनता है।
- `--dry-run` चुनी गई इंस्टॉलेशन का पूर्वावलोकन दिखाता है।
- JSON और गैर-इंटरैक्टिव उपयोग में स्पष्ट Skill चयन, टार्गेट और `--yes` आवश्यक हैं; `--dry-run` पूर्वावलोकन इसका अपवाद है।
- `--ui` के साथ `--skill`, `--target` या `--dry-run` नहीं दिए जा सकते।
- HTTPS प्रकाशक के लिए सटीक `--skill` नाम और उस Skill की हर फ़ाइल सूचीबद्ध करने वाली इंडेक्स आवश्यक है।

स्वचालित सुरक्षा निष्कर्ष इंस्टॉलेशन रोक सकते हैं। `--security-details` मानव-पठनीय आउटपुट में निष्कर्ष दिखाता है। स्पष्ट `--accept-security-risk` उचित है या नहीं, यह तय करने से पहले उन्हें देखें। इंस्टॉल किए गए Skills `agentplugins list` में दिखाई देते हैं और सामान्य रखरखाव कमांड इस्तेमाल करते हैं।

## एक प्रोजेक्ट के लिए इंस्टॉल करें {#install-for-one-project}

स्पष्ट प्रोजेक्ट स्कोप [CLI 0.1.93 और उसके बाद](https://github.com/777genius/universal-agent-plugins/releases/tag/agentplugins-v0.1.93) उपलब्ध है। मौजूदा डायरेक्टरी चुनें और हर कमांड में स्कोप दें:

संगत और समीक्षा की गई कैटलॉग प्रविष्टि के लिए पूरा commit SHA वाला Git स्रोत और उपयुक्त एजेंट चुनें। Directory v1 के `context7` जैसे उपनाम केवल user scope में मान्य हैं। `OWNER/REPOSITORY`, `FULL_COMMIT_SHA` और `PACKAGE_PATH` बदलें; पैकेज रिपॉज़िटरी की जड़ में हो तो `//PACKAGE_PATH` हटाएँ।

टेम्पलेट: `github:OWNER/REPOSITORY@FULL_COMMIT_SHA//PACKAGE_PATH`। नीचे दिया कमांड GitLab के वास्तविक ऐतिहासिक कमिट का उदाहरण है; इसका अर्थ यह नहीं कि वह संस्करण अभी कैटलॉग में समीक्षित है। नई स्थापना के लिए कैटलॉग से मौजूदा समीक्षित स्रोत लें।

```bash
agentplugins add github:777genius/universal-agent-plugins@2ddbb99dd190c1792b79904f9875e6322bccd243//plugins/gitlab --target codex --scope project \
  --project-root /path/to/project --dry-run
agentplugins skills add owner/repository --ui --scope project \
  --project-root /path/to/project
```

पहली कमांड पूर्वावलोकन दिखाती है; लागू करने के लिए तैयार हों तो `--dry-run` छोड़ दें। दूसरी कमांड चुने हुए स्कोप का चयन इंटरफ़ेस खोलती है और उपयोगकर्ता का चयन लागू कर सकती है। `--project-root` न देने पर स्पष्ट प्रोजेक्ट स्कोप कमांड चलाने वाली डायरेक्टरी इस्तेमाल करता है। वह पैरेंट फ़ोल्डर नहीं खोजता। अन्यथा add और रखरखाव कमांड उपयोगकर्ता स्कोप चुनती हैं। CLI 0.1.94 में स्रोत आर्ग्युमेंट के बिना `install` प्रोजेक्ट स्कोप तभी चुनता है जब ठीक वर्तमान फ़ोल्डर में नियमित `uap.toml` फ़ाइल हो; स्पष्ट स्कोप प्राथमिक होता है। सख्त लॉक व्यवहार के लिए [बहाली के नियम](./manage) देखें।

टार्गेट को माँगे गए प्रोजेक्ट घटकों का समर्थन करना चाहिए। ChatGPT प्रोजेक्ट इंस्टॉलेशन स्पष्ट रूप से असमर्थित है। VS Code एक लोकल फ़ोल्डर के लिए `.github/skills` और `.vscode/mcp.json` में अपने स्वामित्व वाले `servers` सदस्य तैयार करता है। उसका परिणाम **Prepared** रहता है: वर्कस्पेस/सर्वर ट्रस्ट की समीक्षा करें और क्लाइंट सेटिंग देखें। यह मेटाडेटा अवलोकन MCP शुरू होने, टूल कॉल या मॉडल उपयोग का प्रमाण नहीं है।

पाथ और सक्रियण सीमाओं के लिए [प्रोजेक्ट इंस्टॉलेशन गाइड](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_INSTALLATION.md) और [हर क्लाइंट की प्रोजेक्ट सीमाएँ](https://github.com/777genius/universal-agent-plugins/blob/main/docs/PROJECT_CLIENT_SUPPORT.md) पढ़ें। आगे [रखरखाव और बहाली](./manage) देखें।
